# Контракт агента KudoConnect v1

Автор: y9kudo. API экспортируется из `kudoconnect`; описание типов находится в [index.d.ts](../index.d.ts).

## Жизненный цикл

`createKudoConnect(options)` создаёт один клиент. `await connect()` завершается после получения позиции, здоровья и чанка под игроком. Один экземпляр используется для одной сессии. `await close()` отменяет действие, выключает физику и закрывает сокет. Даже при исключении вызывайте `close` в `finally`.

Параметры: `host`, `port`, `username` (1–16 латинских букв, цифр или `_`), `version: '1.21.1'`, `auth: 'offline'`, `viewDistance: 2..32`, `connectTimeoutMs: 1000..60000`. Запрашиваемая дальность ограничивается настройками сервера.

## Наблюдение

`observe()` возвращает отдельную копию JSON с `contract: 'kudoconnect.agent'` и `version: 1`. Поля:

| Поле | Значение |
| --- | --- |
| `self` | Позиция, скорость, углы в градусах, здоровье, голод, измерение, состояние подключения и среды |
| `inventory` | Только ненулевые количества `minecraft:item`; отсутствующий предмет означает 0 |
| `entities` | Полученные от сервера сущности, позиции, скорости и здоровье, когда известно |
| `world` | Измерение, номер изменения кеша, количество загруженных чанков |
| `combat.attackers` | Недавние источники урона, подтверждённые пакетом сервера |
| `drops` | Наблюдаемые предметы на земле |

`world.blockAt(position)` возвращает блок или `null`, если он неизвестен. `findBlocks({ classes: ['#logs'], position, radius: 64, properties: { axis: 'y' } })` ищет только в полученных чанках. Результат содержит расстояния и `truncated`: при исчерпании бюджета отсутствие находки не доказывает отсутствие блока. `registerClass('building', ['stone', 'cobblestone'])` добавляет класс. `blockUpdate`, `chunkLoad`, `chunkUnload` доступны на `client.world`.

## Действия

`await execute({ skill, args }, { signal, priority })` имеет одного исполнителя. Действие с большим приоритетом отменяет текущее и ждёт освобождения исполнителя. Равный/меньший приоритет при занятом клиенте отклоняется. `AbortSignal` отменяет ожидания и следующие операции; уже подтверждённые сервером изменения не откатываются.

| Навык | Пример `args` | Что проверяется |
| --- | --- | --- |
| `gather` | `{ block: '#logs', count: 1 }` | Добыча и прирост предмета |
| `dig` | `{ x: 5, y: 64, z: 2 }` | Реальное изменение блока |
| `collect` | `{ item: 'minecraft:birch_log', timeoutMs: 8000 }` | Прирост инвентаря; исчезновение сущности недостаточно |
| `goto` | `{ x: 5, y: 64, z: 2, range: 1 }` | Движение по наблюдаемой опоре; серверные коррекции могут прервать его |
| `place` | `{ x: 5, y: 64, z: 2, block: 'cobblestone' }` | Блок, полученный от сервера |
| `shoot` | `{ entityId: '42', weapon: 'bow' }` | Снаряд/расход боезапаса; `hitConfirmed: false` |
| `drop` | `{ item: 'birch_log', count: 1 }` | Уменьшение инвентаря, не получение другим игроком |
| `eat` | `{ item: 'bread' }` | Уменьшение еды и увеличение сытости |
| `guard` | `{ durationMs: 400 }` | Запрос использования щита; не доказательство блокирования урона |
| `attack` | `{ entityId: '42' }` | Отправка удара в допустимой дистанции; не доказательство урона |

`shoot` поддерживает обычные/спектральные/эффектные стрелы; фейерверки арбалета отклоняются. Боевые навыки требуют `allowPlayer: true` для целей-игроков. `describe().skills` — фактически доступные навыки. Не считайте любое разрешившееся Promise доказанным изменением мира: смотрите поля результата.

## Расширение

```js
const client = new KudoConnect(options, {
  createProtocolClient: options => myTransport(options),
  physics: (state, controls, getBlock) => myPhysics(state, controls, getBlock)
});
client.registerSkill('inspect', async (args, { client, signal }) => {
  signal.throwIfAborted();
  return client.observe();
});
```

Протокол должен реализовать используемый интерфейс `minecraft-protocol`: события пакетов, `write`, `end`, `state`, `socket`. Подмена транспорта сама по себе не добавляет поддержку других игровых версий. Пользовательский навык обязан учитывать сигнал отмены и завершаться; ядро не запускает следующее действие параллельно с незавершённым предыдущим.

## Обмен данными

`createFleet({ count: 1..10 })` управляет подключениями и доставкой сообщений в одном процессе. Если вход одного клиента не удался, все уже открытые клиенты закрываются. Список имён по умолчанию экспортируется как `DEFAULT_AGENT_NAMES`. Для воспроизводимых испытаний передавай явный массив `names`.

`KudoPeer` получает `id`, `team`, список `peers`, функцию `send(envelope)` и необязательные `clock`, `settleMs`. Сообщение содержит версию, группу, отправителя, получателя, последовательность, тему, JSON-нагрузку и время истечения. Лимит сообщения 16 KiB, TTL 100–30000 мс; память повторов ограничена. `receive` проверяет группу, получателя, TTL и повторы. Транспорт между разными процессами должен обеспечивать аутентичность отправителя и согласованное время: это не встроенная защита от поддельных сетевых пакетов.

Передача сообщения о древесине не переносит древесину. Для физического обмена приложение сближает агентов, выполняет `drop`, затем `collect` и проверяет инвентари обоих; другой игрок может подобрать предмет первым. Автоматической атомарной передачи предметов нет.

## Диагностика

`metrics` содержит число пакетов, действий, ошибок, коррекций, максимальное время тика и предупреждения декодера. `trace` хранит последние 128 действий, исход и длительность. `subscribeUrgent` подписывает на собственный урон; возвращает функцию отписки. События `action`, `warning`, `fault`, `entity`, `damage`, `end` доступны через `on`.

## Новые действия и жизненный цикл

- `equipArmor { item }`: выбор предмета и подтверждённая смена соответствующего слота брони. `inventory.equipment()` показывает броню, `ownedCount(item)` включает её в количество.
- `prepareBed {}`: поиск пригодной кровати, либо крафт и установка из доступных материалов.
- `sleep { x?, y?, z?, maxWaitMs? }`: ночь в Overworld, подход вплотную, подтверждение сна; ожидание ограничено 1–30 секундами, затем пробуждение. Без координат сначала вызывается подготовка кровати.
- `time.timeOfDay`, `state.sleeping` и события `time`/`sleep`/`wake` отражают серверные данные.

- `craft { item, count }`: новые предметы, округление до партии; 2×2 или верстак 3×3.
- `ensureStation { station, gather? }`: верстак или печь; найти, создать и поставить.
- `smelt { item, count, input?, fuel?, fuelCount? }`: обычная печь, результат подтверждён сервером.
- `findStorages({ radius: 64, count: 32 })`: сундуки, двойные сундуки, бочки, шалкеры; результат содержит `truncated`.
- `lootChest { x, y, z, maxStacks: 54 }`: забрать доступное содержимое в пределах вместимости.
- `lookAt(position, { turnSpeed: 540 })` и `waitForLook()`: плавный поворот и ожидание.
- `navigate { x, y, z, sprint?, sprintJump?, bridge? }`: автоматические ускорение и мост по известному миру.
- `respawn({ timeoutMs: 15000 })`: только из `state.status === 'dead'`; ждёт живого состояния и чанка.

Подробное руководство: [крафт и движение](CRAFTING-MOVEMENT.md).

## Падения и измерения в 0.5.0

`assessFall({height, health, landing, minHealthAfter:6, maxDamage:6})` возвращает прогноз урона, остаток здоровья, `survivable` и `allowed`. `landing` — наблюдаемый блок. Обычная броня не уменьшает расчётный урон падения. Неизвестная опора, опасные блоки, жидкости и неконтролируемый отскок слизи отклоняются.

Параметры клиента: `maxDrop` (1–32, в навигации по умолчанию 16), `fallHealthReserve` и `maxFallDamage` (0–20, по умолчанию 6). Допустимая высота не означает обязательный прыжок: маршрут проверяет суммарный урон, место приземления и текущее здоровье перед спуском. Оценка не моделирует все эффекты и зачарования.

| Действие | Аргументы | Подтверждение |
| --- | --- | --- |
| `ignitePortal` | `origin: {x,y,z}`, `axis: "x"` или `"z"` | Известная рама 4×5 и появление блоков портала |
| `fillEndFrame` | `x,y,z` | Свойство `eye: true` серверного блока |
| `throwEye` | `{}` | Расход предмета и единственный наблюдаемый полёт |
| `enterPortal` | `x,y,z,dimension` | Новое измерение, позиция, здоровье и загруженный чанк |

`throwEye` отклоняет бросок при другом игроке ближе 24 блоков: серверная сущность ока не даёт надёжного поля владельца. Последние 32 наблюдения доступны в `observe().endgame.eyes`.

Переход сохраняет серверный инвентарь; текущие сущности и чанки заменяются данными нового измерения. Возрождение после смерти остаётся отдельным `respawn()`. Клиент не устанавливает координаты для обхода портала и не отправляет команды администратора.
