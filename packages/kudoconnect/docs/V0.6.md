# KudoConnect 0.6.0

KudoConnect остаётся самостоятельной библиотекой. Внутри нет зависимости от MCKudo или Mineflayer. Нейросеть размещена в MCKudo, а транспорт предоставляет события `navigationStep` и необязательную `navigationPolicy.cost(from, to, kind)`.

## Подключение и версии

```js
import { createKudoConnect, versionSupport, listVersionSupport } from 'kudoconnect';
console.table(listVersionSupport());
console.log(versionSupport('26.3'));
const client = createKudoConnect({username:'Atlas',version:'1.21.1',auth:'offline'});
await client.connect();
```

Нативные профили — **1.21 и 1.21.1**. У 1.21.1 есть реальные игровые прогоны, у 1.21 отдельно проверено совпадение протокола, но не выполнен игровой прогон. Остальные версии требуют адаптации игровых действий. Поля `catalog`, `transport` и `native` у `versionSupport()` отвечают на разные вопросы. 26.3 сейчас не является поддерживаемым нативным профилем.

Реестр создаётся при подключении или явном обращении к игровым данным. Создание клиента и `snapshot()` до подключения не разворачивают его.

## Книга мира

```js
await client.waitFor(() => client.recipeBook.received, {event:'recipes',timeoutMs:10000});
console.log(client.recipeBook.snapshot());
console.log(client.recipeBook.recipesFor('wooden_pickaxe'));
```

Сервер передаёт всю декларацию; KudoConnect нормализует только запрошенные результаты. Повторная декларация сбрасывает кэш. Крафт использует серверные альтернативы ингредиентов, например смешанные доски в обычном верстаке. Рецепты с возвратом ёмкостей не считаются исполнимыми обычным крафтом.

## Навигация и новые действия

- `navigate`: собственный путь по известным блокам, проверка опоры, урона падения и пересечения с игроками; spectator не блокирует проход.
- `pillar`: прыжок и установка под ногами, 1–8 блоков за действие. Только подтверждённое сервером размещение.
- `descendPillar`: разбор собственных записанных блоков с контролем посадки.
- `smith`: улучшение алмазного предмета шаблоном и незеритовым слитком, с проверкой компонентов результата.
- `ensureStation`: дополнительно `smithing_table` и `brewing_stand`; материалы должны быть доступны.
- `smelt`: дополнительно `ancient_debris` → `netherite_scrap`.

```js
await client.execute({skill:'smith',args:{item:'diamond_pickaxe'}});
```

Кузнечный стол ищется поблизости; при отсутствии создаётся из имеющихся материалов. Алмазная броня в слоте экипировки переносится в инвентарь перед улучшением. Нужны свободные слоты. Чужое занятое окно не расходуется. Если сервер изменил компоненты результата неожиданным образом, операция завершается ошибкой.

Обработка End-кристаллов требует и взрыва, и удаления сущности. Исчезновение дракона не считается победой. Информация о подтверждённой смерти и собственном уроне доступна в `client.endgame`.

Для своего планировщика используйте `planRoute({ ..., edgeCost })`: callback возвращает неотрицательную добавку 0–1000. Он не отменяет геометрические ограничения. Нейросеть или другая политика может жить в вашем приложении без зависимости KudoConnect от её реализации.
