# Крафт, движение и восстановление

## Строительство под собой

`await client.execute({skill:'pillar',args:{count:3,block:'dirt'}})` поднимает агента на три блока обычными прыжками. Нужны полная опора, здоровье больше 8, свободное пространство и материалы. Количество — 1–8; без `block` выбираются обычные полные блоки по стоимости. Каждый шаг подтверждается изменением мира, расходом предмета и посадкой. Коррекция позиции прекращает действие.

`await client.execute({skill:'descendPillar',args:{count:3}})` разбирает собственный подтверждённый столб по одному блоку. Требуется известная безопасная опора под каждым снимаемым блоком. После переподключения память установленного столба не сохраняется. Обычный `dig` под ногами запрещён.

`evade` принимает `{from:{x,y,z}}` и выбирает известный путь отхода. Выстрелы `shoot` плавно наводятся на цель; близкие кристаллы и сидящие фазы дракона отклоняются. `client.endgame` хранит подтверждения взрывов/удаления кристаллов и смерти дракона, отдельно указывая наличие серверного урона агента.

KudoConnect содержит исполнители Minecraft Java 1.21.1; выбор долговременных целей принадлежит подключаемому мозгу. Автор — y9kudo.

```js
import {createKudoConnect} from 'kudoconnect';
const client=createKudoConnect({username:'Oliver',auth:'offline'});
try {
  await client.connect();
  if(client.state.status==='dead')await client.respawn();
  await client.execute({skill:'gather',args:{block:'#logs',count:1}},
    {signal:AbortSignal.timeout(60000)});
  await client.execute({skill:'ensureStation',args:{station:'crafting_table'}});
} finally {await client.close();}
```

`craftingRecipes(registry, item)` показывает исполняемые статические рецепты. `chooseCraftingRecipe(registry,item,inventory)` выбирает материалы по слотам с учётом остатков. `craft.count` означает новое количество результата, а не количество в конечном инвентаре; партия может дать больше. Смешанные доски разрешены только рецептам с соответствующим тегом, порода специальных деревянных предметов сохраняется. Рецепты с возвратом ёмкости и специальные динамические рецепты пока не выполняются.

Крафт 2×2 работает в инвентаре, 3×3 открывает верстак. Исполнитель ждёт ответов сервера на перемещение ингредиентов и получение результата. Отмена закрывает окно; подтверждённые изменения не откатываются.

`ensureStation({ station: 'crafting_table' | 'furnace', gather: true })` — аргументы одноимённого навыка. Сначала ищется доступная станция, затем собираются базовые материалы, создаётся предмет и проверяется постановка. `gather:false` запрещает дополнительную добычу.

`smelt` принимает `item`, `count` 1–64, необязательные `input`, `fuel`, `fuelCount`. Поддержаны обычные руды, уголь из древесины, основная еда и базовые строительные результаты. `smeltingRecipe` возвращает поддерживаемое сырьё и время; `fuelItems` — число переплавок на единицу топлива. Существующие чужие предметы в печи не расходуются. Параллельные клиенты одного процесса ждут освобождения печи. Передавай достаточный тайм-аут: обычный предмет плавится примерно десять секунд при 20 TPS.

`lookAt` не телепортирует углы к цели: поворот выполняется физическими тиками. `waitForLook` ждёт завершения, `cancelLook` отменяет цель. `turnSpeed` задаётся в градусах/секунду (30–1440). Немедленный поворот доступен явно через `immediate:true`.

`navigate` объединяет прямые шаги, спринтит при достаточном голоде, прыгает на длинном проверенном участке. Прыжок не применяется вслепую над неизвестной опорой. Аргументы `sprint:false`, `sprintJump:false`, `bridge:false` отключают соответствующие части на одном маршруте.

`excavate:true` разрешает расчистку обычного грунта и камня на маршруте, включая потолок для подъёма по ступени. Нужен инструмент, позволяющий получить дроп; неизвестные области, жидкости и соседние падающие блоки запрещают такую расчистку. Опоры под текущей и следующей позицией не добываются. Подход к станции/целевому блоку сначала проверяет обычные маршруты и затем эту возможность выхода из выработки. Пользовательский A* включает добычу через `canDig(block, position)`; исполнитель подтверждает каждый снятый блок.

Поиск учитывает изменения каждой ветви плана: снятый блок становится воздухом, построенный мост — опорой. Разные изменения мира различают состояния поиска. Поэтому будущий шаг не может опираться на ранее выкопанный блок. Расчистка ограничена 32 блоками на один маршрут; длинную выработку выполняй несколькими действиями с новым наблюдением.

`bridgeMaterials` отбирает безопасные полные блоки из инвентаря. Земля, камень, доски, шерсть и бетон могут использоваться совместно. Падающие, функциональные, опасные и ценные блоки исключены. Опции клиента `bridgeReserve` и `bridgeItemValue` задают запас и стоимость расхода. Сервер должен подтвердить каждый новый блок до перехода.

Поиск видит полученные чанки, а не весь мир. Палитры однородных и многозначных секций пропускают заведомо неподходящие объёмы. `truncated:true` означает неполный поиск. Для Java 1.21.1 используется отдельный исправленный декодер списка рецептов: [исходное исправление minecraft-data](https://github.com/PrismarineJS/minecraft-data/pull/1291). Глобальные данные и кеш транспорта не изменяются.

При смерти `status` становится `dead`, действие отменяется. `respawn()` запрашивает возрождение и ждёт нового живого состояния. Вне смерти он отклоняется. Для нового подключения после `close()` нужен новый клиент.


## Поиск пути без блокировки обработки событий

Нативные `navigate`, подход к добыче и поиск подхода к луту используют `planRouteAsync`. Публичный пример:

```js
import { planRouteAsync } from 'kudoconnect';
const view = client.world.createReadView();
const route = await planRouteAsync({
  start: { x: 0, y: 64, z: 0 }, goal: { x: 10, y: 64, z: 0 },
  getBlock: p => view.blockAt(p), maxNodes: 3000,
  signal: new AbortController().signal
}, { sliceMs: 2, nodesPerSlice: 64, getRevision: () => view.isCurrent() });
```

`client` — подключённый KudoConnect. Общая очередь процесса чередует поиски: мягкий суммарный бюджет 4 мс, порция одного поиска до 64 узлов или 2 мс. Отдельный узел обрабатывается целиком. Изменение прочитанного чанка отклоняет Promise; посторонние обновления не мешают. Синхронный `planRoute` остаётся доступен. Найденный маршрут ещё не означает выполненное движение. Собственную очередь можно создать через `createWorkScheduler({budgetMs,maxJobs})` и передать вторым аргументом как `scheduler`.

`client.snapshot().metrics.timing` содержит `effectiveHz`, `meanIntervalMs`, `p95IntervalMs`, `maxIntervalMs`, `delayedTicks`, `samples`, `ticks`. Окно — 128 последних интервалов локального таймера; задержанным считается интервал длиннее 75 мс. Это не сетевой ping и не серверный TPS. До накопления интервалов оценки равны `null`; после отключения сохраняется последняя статистика.

`metrics.navigation` содержит общую статистику очереди всех клиентов процесса: ожидающие, завершённые, ошибочные и отменённые задачи, число порций и максимальное время порции. `createWorkScheduler.submit()` принимает синхронный итератор, поддерживает `signal`, ограничение размера и очистку при отмене. Это распределение времени цикла событий, а не жёсткий ограничитель CPU.
## Мосты и промежуточные маршруты 0.6.0

`planRoute` / `planRouteAsync` принимают `allowPartial: true`. План `status: 'planned', partial: true` содержит проверенный промежуточный `target`; приложению нужно пройти этот участок и пересчитать путь. По умолчанию частичный результат выключен. Неизвестные блоки не становятся воздухом или опорой.

Во время `navigate` мост расходует безопасные полные неподвижные блоки из инвентаря. Исполнитель приседает, подтверждает установленную опору и уменьшение количества материала перед шагом, удерживает край в физике и выключает приседание при отмене. Песок, гравий, ценные блоки и станции не расходуются случайно. Автоматическую добычу недостающего материала реализует высокоуровневая цель MCKudo; самостоятельному KudoConnect приложение передаёт уже подготовленные материалы.
