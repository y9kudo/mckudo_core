# Крафт, движение и восстановление

KudoConnect содержит исполнители Minecraft Java 1.21.1; выбор долговременных целей принадлежит подключаемому мозгу. Автор — y9kudo.

```js
import {createKudoConnect} from 'kudoconnect';
const client=createKudoConnect({username:'Oliver',auth:'offline'});
try {
  await client.connect();
  if(client.state.status==='dead')await client.respawn();
  await client.execute({skill:'gather',args:{block:'#logs',count:1}},
    {signal:AbortSignal.timeout(60000)});
  await client.execute({skill:'ensureStation',args:{station:'crafting_table'}});
} finally {await client.close();}
```

`craftingRecipes(registry, item)` показывает исполняемые статические рецепты. `chooseCraftingRecipe(registry,item,inventory)` выбирает материалы по слотам с учётом остатков. `craft.count` означает новое количество результата, а не количество в конечном инвентаре; партия может дать больше. Смешанные доски разрешены только рецептам с соответствующим тегом, порода специальных деревянных предметов сохраняется. Рецепты с возвратом ёмкости и специальные динамические рецепты пока не выполняются.

Крафт 2×2 работает в инвентаре, 3×3 открывает верстак. Исполнитель ждёт ответов сервера на перемещение ингредиентов и получение результата. Отмена закрывает окно; подтверждённые изменения не откатываются.

`ensureStation({ station: 'crafting_table' | 'furnace', gather: true })` — аргументы одноимённого навыка. Сначала ищется доступная станция, затем собираются базовые материалы, создаётся предмет и проверяется постановка. `gather:false` запрещает дополнительную добычу.

`smelt` принимает `item`, `count` 1–64, необязательные `input`, `fuel`, `fuelCount`. Поддержаны обычные руды, уголь из древесины, основная еда и базовые строительные результаты. `smeltingRecipe` возвращает поддерживаемое сырьё и время; `fuelItems` — число переплавок на единицу топлива. Существующие чужие предметы в печи не расходуются. Параллельные клиенты одного процесса ждут освобождения печи. Передавай достаточный тайм-аут: обычный предмет плавится примерно десять секунд при 20 TPS.

`lookAt` не телепортирует углы к цели: поворот выполняется физическими тиками. `waitForLook` ждёт завершения, `cancelLook` отменяет цель. `turnSpeed` задаётся в градусах/секунду (30–1440). Немедленный поворот доступен явно через `immediate:true`.

`navigate` объединяет прямые шаги, спринтит при достаточном голоде, прыгает на длинном проверенном участке. Прыжок не применяется вслепую над неизвестной опорой. Аргументы `sprint:false`, `sprintJump:false`, `bridge:false` отключают соответствующие части на одном маршруте.

`bridgeMaterials` отбирает безопасные полные блоки из инвентаря. Земля, камень, доски, шерсть и бетон могут использоваться совместно. Падающие, функциональные, опасные и ценные блоки исключены. Опции клиента `bridgeReserve` и `bridgeItemValue` задают запас и стоимость расхода. Сервер должен подтвердить каждый новый блок до перехода.

Поиск видит полученные чанки, а не весь мир. Палитры однородных и многозначных секций пропускают заведомо неподходящие объёмы. `truncated:true` означает неполный поиск. Для Java 1.21.1 используется отдельный исправленный декодер списка рецептов: [исходное исправление minecraft-data](https://github.com/PrismarineJS/minecraft-data/pull/1291). Глобальные данные и кеш транспорта не изменяются.

При смерти `status` становится `dead`, действие отменяется. `respawn()` запрашивает возрождение и ждёт нового живого состояния. Вне смерти он отклоняется. Для нового подключения после `close()` нужен новый клиент.
