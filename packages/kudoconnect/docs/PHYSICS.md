# Физика и прицеливание

`stepPhysics` — собственный ограниченный интегратор движения стоящего игрока Java 1.21.1. Один вызов соответствует одному игровому тику 50 мс. Источник истинного здоровья, предметов, блоков и коррекций позиции — сервер.

Базовые контакты: твёрдые формы блоков, жидкости, лестницы, паутина, мёд, слизь и скользкие поверхности. Неизвестные чанки запрещают движение. `environmentAt` возвращает среду, опору, трение, контактные блоки и опасность; лава никогда не считается обычным воздухом. Течения вычисляются по наблюдаемым соседним уровням, поэтому неизвестный сосед не порождает вымышленный поток. Паутина гасит импульс, слизь отражает падение (кроме sneak), мёд замедляет и снижает прыжок. Это базовая модель; позы плавания, эффекты, зачарования, движущиеся поршни и транспорт требуют дополнительных профилей.

Численные коэффициенты проверялись по открытой [реализации Prismarine Physics](https://github.com/PrismarineJS/prismarine-physics/blob/master/index.js) и [ветке NeoForge для 1.21.1](https://github.com/neoforged/NeoForge/blob/1.21.1/patches/net/minecraft/world/entity/LivingEntity.java.patch). Их проверка не заменяет игровые сравнения: специальные поверхности пока проверены модельными тестами, а обычное движение дополнительно проверялось на сервере.

## Баллистика

```js
import { solveAim } from 'kudoconnect';
const solution = solveAim({
  origin: { x: 0, y: 65.52, z: 0 },
  target: { x: 24, y: 65, z: 0 },
  targetVelocity: { x: 0, y: 0, z: 0.1 }, // блоков за игровой тик
  weapon: 'bow', chargeTicks: 20,
  getBlock: position => client.world.blockAt(position)
});
```

Решатель ищет пересечение траектории с движущейся целью, проверяет точное пересечение отрезков с формами блоков и отказывает при неизвестном пути. Скорость цели считается постоянной на коротком горизонте. Параметры `bow`, `crossbow`, `trident` задают базовую скорость, сопротивление и гравитацию. Численный результат — прогноз без случайного разброса; ускорение цели, вода или изменившийся мир могут сделать его неверным.

`yaw` и `pitch` выдаются **в сетевых градусах Minecraft**, положительный pitch направлен вниз. `targetVelocity` и `inheritedVelocity` — блоки за тик, не за секунду. `traceProjectile` возвращает путь или первое препятствие. `solveAim` не стреляет: для реального действия используйте `client.execute({ skill: 'shoot', args: { entityId, weapon: 'bow' } })`.

Исполнитель перед выстрелом пересчитывает прицел по свежей позиции. Он выдерживает время натяжения/заряжания, проверяет боеприпасы и ждёт серверного подтверждения расхода/снаряда. Отмена натянутого лука переключает слот, не отпуская стрелу в прежнюю цель. `shotServerConfirmed` и `hitConfirmed` различаются: попадание в этой версии не объявляется подтверждённым.

Структура `charged_projectiles` арбалета проверена по [протокольной схеме 1.21.1](https://github.com/PrismarineJS/minecraft-data/blob/master/data/pc/1.21.1/proto.yml). Исполнитель стреляет обычными стрелами; фейерверки и фактический бросок трезубца пока не реализованы.
