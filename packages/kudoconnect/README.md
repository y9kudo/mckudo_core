# KudoConnect

**Самостоятельная библиотека Minecraft Java · v0.5.0 · автор y9kudo · MIT**

KudoConnect подключает программных агентов к серверу, читает мир и исполняет действия. Можно подключить от одного до десяти агентов в одном приложении и передавать между ними данные без игрового чата. Решения принимает ваше приложение: обычный JavaScript, планировщик, RL-модель, LLM или MCKudo Core.

Mineflayer и MCKudo не нужны для установки и выполнения KudoConnect. Кодирование сетевого протокола предоставляет `minecraft-protocol`; реестры, чанки и формы блоков — `minecraft-data`, `prismarine-chunk`, `prismarine-block`. Очередь действий, состояние клиента, физика, поиск и обмен сообщениями находятся в этой библиотеке.

## Установка из исходников

Требуется Node.js 22+. Эта версия ещё не опубликована в npm: не устанавливайте случайный одноимённый пакет.

Клонируйте отдельный репозиторий (либо откройте `packages/kudoconnect` внутри MCKudo):

```powershell
git clone https://github.com/y9kudo/kudoconnect.git
cd kudoconnect
npm.cmd ci
npm.cmd test
npm.cmd pack
```

В папке собственного приложения установите полученный архив:

```powershell
npm.cmd init -y
npm.cmd pkg set type=module
npm.cmd install C:/путь/к/kudoconnect-0.5.0.tgz
```

Создайте `index.js`:

```js
import { createKudoConnect } from 'kudoconnect';

const alice = createKudoConnect({
  host: '127.0.0.1', port: 25565,
  username: 'Alice', version: '1.21.1', auth: 'offline'
});
try {
  await alice.connect();
  console.log(alice.observe());
  await alice.execute({ skill: 'gather', args: { block: '#logs', count: 1 } });
} finally {
  await alice.close();
}
```

Запуск: `node index.js`. `#logs` включает разные породы; поиск выбирает ближайшие наблюдаемые стволы, затем проверяет достижимость. Успех добычи требует появления предмета в инвентаре.

## Несколько агентов

```js
import { createFleet } from 'kudoconnect';

const fleet = createFleet({ count: 2, names: ['Alice', 'Blake'] }); // максимум 10
try {
  await fleet.connect();
  fleet.peers.get('Blake').on('message', message => console.log(message));
  fleet.peers.get('Alice').send('discovery', {
    kind: 'wood', position: { x: 10, y: 64, z: 5 }
  }, { to: 'Blake' });
} finally {
  await fleet.close();
}
```

Это транспорт внутри процесса: Minecraft chat-пакеты не используются. Каждый клиент хранит собственные серверные наблюдения. Сообщение соседа не превращает неизвестный чанк в известный и не подтверждает получение предмета. Для разных процессов можно подключить свой транспорт к `KudoPeer`; встроенного сетевого сервиса обмена пока нет.

`claim(resource)` распространяет намерение, `owner(resource)` после короткого периода ожидания выбирает наименьший `bid`, затем имя по алфавиту. Решение вычисляется у каждого участника. `release(resource)` освобождает задачу; намерения истекают по TTL. При разделении сети единственный исполнитель не гарантируется — это согласование намерений, не распределённая транзакция.

На сервере должно быть достаточно свободных мест: для 10 агентов и одного человека нужно минимум 11. Параметр библиотеки не меняет настройки сервера.

## Возможности этой версии

| Область | Реализовано |
| --- | --- |
| Подключение | Java 1.21.1, offline, сервер или мир, открытый по LAN; у LAN свой порт |
| Мир | Чанки, формы блоков, свойства состояний, ограниченный асинхронный поиск, классы, события изменений |
| Исполнение | `look`, `lookAtPlayer`, `lootChest`, `select`, `equipArmor`, `craft`, `ensureStation`, `smelt`, `prepareBed`, `sleep`, `ignitePortal`, `fillEndFrame`, `throwEye`, `enterPortal`, `goto`, `navigate`, `dig`, `gather`, `collect`, `place`, `attack`, `combat`, `guard`, `shoot`, `drop`, `eat`, `wait` |
| Игроки и хранилища | Список игроков отдельно от наблюдаемых позиций, взгляд по UUID, отменяемое внимание, сундуки/бочки, подтверждённый перенос в инвентарь |
| Физика | Стоящий игрок, столкновения, прыжок, базовая вода/лава и течения по уровням, паутина, слизь, мёд, лёд, лестницы |
| Баллистика | Упреждение движущейся цели, гравитация, сопротивление, препятствия; bow/crossbow, отдельный расчёт trident |
| Кооперация | 1–10 клиентов, сообщения, адресная доставка, TTL, подавление повторов и намерения |
| Диагностика | `observe`, `snapshot`, `metrics`, ограниченный `trace`, события действий/урона, отмена и приоритеты |
| Расширение | `registerSkill`; внедрение транспорта и физики через второй аргумент `new KudoConnect()` |

Наличие физики воды не включает построение водных маршрутов: текущий наземный планировщик обходит жидкости. Лава помечается как опасная; здоровье и смерть сообщает сервер. Модель ещё не покрывает позы плавания, транспорт, элитры, поршни, все эффекты и зачарования. Стрельба не гарантирует попадания: цель может ускориться, сервер — внести коррекцию, стрела — иметь разброс.

Реализованы обычный крафт 2×2/3×3, станции, плавка, броня, кровати, порталы и наблюдение ока. Зельеварение и специальные динамические рецепты требуют дальнейших исполнителей. Полное прохождение мира пока не подтверждено. Другие версии, Microsoft-вход и модовые сетевые профили не объявлены поддержанными до реализации и проверок.

Совместимость чтения `declare_recipes` для Java 1.21.1 исправлена локальным декодером: в игровом испытании прочитаны 1 290 рецептов без ошибок. Переход между измерениями сохраняет инвентарь и ожидает новую позицию/чанк; смерть обрабатывается отдельным `respawn()`. Проверки переходов пока протокольные, полная игровая экспедиция не завершена.
