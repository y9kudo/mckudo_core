# OvermindMC 1.0.0-Arthas-beta1

**Version Arthas · Public beta · Created by y9kudo · MIT**

This release improves how an agent turns a resource goal into physical actions, keeps movement continuous and reacts during combat. OvermindMC supplies planning and policies; the independent OMConnect client observes the world and executes actions, with OMVectorize handling spatial calculations. Mineflayer remains optional.

## AI and resource planning

An application can request `{'minecraft:diamond': 1}` without supplying an ordered recipe script. The existing resource planner resolves crafting, smelting and tool prerequisites against the connected world's catalog. Beta1 extends that loop with **elevated resource access**: when an observed mineral is floating above walkable ground, the core can plan the construction needed to reach it.

The new policy:

1. Selects a known, supported side column beside the target, checking clearance, placement permissions and observed player occupancy.
2. Budgets expendable building blocks for the remaining rise and a platform below the ore. If stock is insufficient, it can procure nearby safe soil at the staging ground level.
3. Uses batches of at most eight jump-placements, confirming each landing through OMConnect. A partial column is reused only when the client recorded ownership of its blocks.
4. Stops below the target to attach a drop-catching platform against the ore's underside, then completes the ascent.
5. Mines with the required tool and waits for actual pickup. Sending a dig packet or making the ore disappear is insufficient for completion.

The policy currently bounds the rise to 128 blocks and requires observed geometry. It respects explicit protected regions. Village materials are available in the supplied trial only when the application explicitly enables their harvesting.

The goal-only `test:live:sky-diamond` launcher records recipe dependencies, construction plans, confirmed actions and inventory. It supports a development resume without erasing the original empty-inventory record. The intelligence changes here are **resource planning, spatial policy and reactive control**; this release does not claim that a neural model learned crafting from this trial. Existing DQN/PPO/SAC experiments and the opt-in RL bridge remain separate APIs.

## Navigation and failure memory

- Compatible ground-walking spans retain velocity. Bounded lookahead and footprint-checked corner shortcuts reduce unnecessary stop/start behavior.
- A short-lived, one-use kernel-to-client route handoff avoids repeating the same search when its observed execution conditions remain valid.
- A server position correction immediately invalidates the old route. Movement continues to use collision, support and authoritative world observations.
- Failure memory records **directed transitions**, so one failed entrance does not ban every approach to a destination. Transient occupancy and corrections do not become persistent training failures.
- Schema-one model weights and replay samples remain loadable; obsolete destination-wide bans are discarded during migration.

## Combat, aiming and projectile defense

The dedicated reactive controller reassesses reach, voxel occlusion, shield facing, weapon choice, spacing and critical opportunities without waiting for a completed aim animation or a separate blocking guard action.

- Target velocity is estimated from position observations, with packet-burst coalescing, stale-data decay and teleport resets. Bounded jump forecasts stop at observed landing surfaces.
- Bow and crossbow charging follow fresh interception estimates throughout aiming and release. Smooth look uses bounded angular feed-forward; a shot is released only after its look-ray checks. A release never claims a hit.
- Weapon commitment covers the selected weapon's base cooldown plus 175 ms, preventing shield flicker from repeatedly resetting charged attacks. Directional flanks, cooldown spacing and guarded movement preserve terrain safety checks.
- Ranged aim failures temporarily back off shooting while allowing approach and defense. A facing shield can cancel a tactical draw.
- An independent high-priority projectile guard can interrupt ordinary work or an ongoing bow draw. It predicts body intersections, considers walls and observed aimed bows, follows bounded sparse-arrow estimates, and lowers the shield after danger clears. Minecraft's five-tick shield activation delay still applies.
- Native 1.21/1.21.1 projectile ownership decoding now preserves the actual spawn owner ID; direct damage-source IDs remain separate from attributed shooters. Server shield-block status is observable.

Sending a melee attack does not count as confirmed damage or pursuit progress. PvP authorization remains an application policy; the diamond trial disables attacks against players.

## Connection and packaging

OMConnect responds to common configuration/play ping packets, correcting a reproduced LAN login stall. Core, standalone OMConnect, OMVectorize identities, lockfiles and declarations use `1.0.0-Arthas-beta1`. YourMind retains its independent `alpha1.0` version.

The release workflow runs Linux/Windows checks on Node.js 22/24 before publishing this prerelease. The downloadable packages are:

- `overmindmc-1.0.0-Arthas-beta1.tgz`: core, bundled client, examples and documentation.
- `omconnect-1.0.0-Arthas-beta1.tgz`: independent client.
- `SHA256SUMS.txt`: archive integrity checksums.

Install a downloaded archive with `npm.cmd install <path-to-archive>`. Publishing these GitHub archives does not publish a package to the npm registry. Worlds, auth caches, player traces, Minecraft assets and raw runtime reports are excluded.

## Verification and known limits

The local `npm.cmd run check` suite passes **623 tests**, with no failures, skips or cancellations. Strict public TypeScript checks pass. Coverage includes movement, route handoff, directed failure memory, target-motion prediction, projectile defense, weapon cooldowns and the core's elevated-access decisions.

In the prepared Java **1.21.1** Survival trial, `RowanSky` began with an empty inventory, crafted wooden/stone tools and a furnace, smelted iron, crafted an iron pickaxe, placed an **11-block side column** and an underside platform, mined the supplied floating ore and collected **one diamond**. Final health was **20**. The village and three supplied iron ores were part of the fixture. The trial required a diagnostic reconnect after an `entity_equipment` decode failure; it is not an uninterrupted autonomy or speed benchmark. The underlying decoder incident remains under investigation.

A separate short navigation trial confirmed two route handoffs, zero server position corrections and approximately 20 Hz local physics cadence. These values describe that trial, not a global performance improvement.

The manual equipped PvP development round ended with the agent's death. Improved projectile defense is covered by protocol/physics regressions; another controlled live arrow-blocking match remains necessary. No general bow accuracy or PvP win rate is claimed.

Stable **1.0.0** still requires an independently verified empty-inventory Dragon victory. Broad-version gameplay equivalence, uninterrupted full-game autonomy and comparative performance remain acceptance work.
