# OvermindMC 1.0.0-Arthas-beta2

This build develops the V2 architecture through Navigation V2, World Intelligence and Cognitive Intelligence and the first Task Orchestration/Recovery increment. It retains existing JavaScript/TypeScript APIs and beta1 core checkpoints. It is a development beta, not a completed V2 platform or a stable autonomous gameplay release.

## Perception and combat

- Added bounded semantic event metadata, relevance-first entity selection and explicit visibility budgets/freshness diagnostics.
- Fixed missing inventory in urgent threat observations, which could make equipped agents retreat as if unarmed.
- Added short admissible-target commitment and immediate reselection for close creepers or fresh attributed hits.
- Fixed axis-aligned visibility rays passing along integer block faces without testing adjacent wall geometry.
- Added selective resource-scan reuse, dashboard diagnostics and a synthetic selection benchmark. A short local player-tracking/removal check passed without damage or corrections.
- See [Perception V2](../PERCEPTION-V2.md) for limits and integration details.

## Task orchestration and recovery

- Added dependency graphs, observed resource guards, conditional priorities, bounded retries and action deadlines.
- Added awaited preparation/completion checkpoints and fingerprinted task/program restoration, including nested scenario memory.
- Interrupted item mutations require observed postconditions or explicit retry; navigation can be replanned from fresh observations.
- Agent/main JSON storage now has checksums, unique synced temporary writes, one verified backup, beta1 migration and independent frequent task documents.
- Added opt-in bounded reconnect/death recovery and dashboard dependency/failure/uncertainty diagnostics. Existing visual programs remain schema 1.
- A three-task local Java 1.21.1 movement check passed across reconnect and a separate Node.js process, without damage or server corrections. Full campaign recovery remains separate acceptance work.

## Navigation and execution

- Added a bounded regional route graph and incremental LPA* search with a zero heuristic. Changed connections repair existing shortest-path labels; local voxel A* remains responsible for executable geometry.
- Added scoped navigation sessions, expiring route caches, cancellable superseded requests and separate versioned navigation memory. Imported routes trigger a fresh local search; saved geometry never authenticates itself.
- OMConnect now executes long ground goals as bounded local segments and stops if a segment makes no progress. Regional hints can select intermediate destinations; unknown chunks remain blocked.
- Shared collision-shape and player-body helpers now serve physical collision queries and swimming/flight clearance. Support queries account for partial shapes and extended collision shapes such as fences.
- Added short motion predictions using the existing tick physics and live navigation diagnostics. This does not introduce a second physics clock or an MPC controller.
- Added canonical navigation failures and bounded recovery decisions. Repeated execution failures can block an unchanged goal context instead of retrying indefinitely.

## API and tooling

Cognitive Intelligence adds a shared decision cycle with hard urgency ordering, bounded learned ranking and observable verification/reflection. Symbolic goals can retain valid plan tails and search short replacement connectors. New planner portfolios validate complete proposals from symbolic/HTN/MCTS providers; existing domain models and physical constraints remain authoritative.

Verified intermediate `progress` outcomes now train the cognitive model. Neural planner memory schema 2 retains schema-1 weights and adds session provenance. Frozen checkpoint comparisons reject known training overlap, insufficient evidence and represented-dimension regressions. Public `experience:transition` events support external evidence collection; dashboard diagnostics expose candidate costs and the decision journal.

World Intelligence adds a scoped atlas with observed regions, hazards, anchors and directed return-corridor hints. Resource exploration uses occlusion-aware frontier ranking in CPU workers and shares one A* expansion budget across candidate groups. SQLite schema migration retains old block evidence and air tombstones; agent checkpoints retain their outer format and save atlas state separately.

A contextual 24–16–3 navigation network learns failure, duration and damage estimates with bounded replay and an uncertainty gate. Geometry fingerprints scope exact failure penalties; approximate per-waypoint durations/damage do not become measured training labels. Neural memory schema 3 imports schemas 1 and 2 without dropping their learned weights. These estimates remain costs under deterministic traversal rules.

New public entry points include `createNavigationSession`, `RegionalRouteGraph`, `IncrementalRegionPlanner`, `supportAt`, `predictMotion` and `createNavigationRecovery`. `OMVectorize.planGroundSegmentAsync` exposes the segmented planner while existing ground/swim/flight methods remain available.

Run `npm run benchmark:navigation` for deterministic offline planning fixtures. The output labels planning-only work separately from Minecraft execution, includes repeated-request latency distributions and records CPU/memory observations. Gameplay journals and server launchers remain local QA data; API tests and CI remain public.

## Measured development evidence

On the local Windows/Node.js 24.19.0 development machine, nine-sample planning measurements gave:

| Fixture | Repeated A* p50 | V2 repeated-request p50 | V2 first request |
| --- | ---: | ---: | ---: |
| Flat, 96 blocks | 2.76 ms | 0.16 ms | 8.07 ms |
| Forest, 48 blocks | 2.95 ms | 0.10 ms | 5.20 ms |

The repeated V2 requests reuse an unchanged route; the first request includes cache bookkeeping. These numbers are not a claim that a fresh V2 search is faster. A 10,000-block synthetic planning progression produced 105 bounded segments in approximately 391 ms; no Minecraft character traversed that distance in this benchmark. On a directed 1001-node chain, changing the final connection required 2 incremental expansions after 1001 initial expansions.

Full movement/PvP, partial-block locomotion, mixed ground/swim/portal/elytra execution, prefetched segment handoff and equivalent-condition comparison with another navigator remain separate acceptance work. The ground voxel planner still uses conservative integer-height nodes; support/volume queries alone do not imply complete slab/stair/door locomotion. No autonomous Dragon victory is declared.

A short non-destructive Java 1.21.1 server check passed. A separate passive client observed the test character move 2.014 blocks; the final prediction/server discrepancy was below 0.001 block and no position correction was recorded. This is a connection/execution smoke check, not a long-distance trial. Detailed player/world journals remain private.

A second non-destructive check verified 2.014 blocks of server-observed movement with zero damage/corrections and restored atlas landmarks plus two directed transitions after an on-disk round trip and reconnection. This confirms integration, rather than a gameplay learning-quality result.

A two-checkpoint non-destructive Java 1.21.1 trial also passed: one planning call, a verified intermediate action and a verified completed goal, with two corresponding neural samples. A passive client confirmed both positions with less than 0.001 block discrepancy, zero damage and zero corrections. Offline cognitive comparisons use explicit unit labels and do not imply full-game learning quality.
