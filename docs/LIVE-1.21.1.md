# Первый игровой тест: vanilla Java 1.21.1

Цель: из пустого инвентаря получить **один верстак и минимум четыре палки**. Ядро выбирает цепочку действий из каталога операторов, а Mineflayer выполняет добычу и крафт. Это проверка конкретного сценария, не полного выживания.

Первый игровой тест выполнен 22 сентября 2026 года: из пустого инвентаря получены один верстак, четыре палки и две оставшиеся доски. [Сохранённый результат](results/vanilla-1.21.1.json). Было шесть действий и два вызова Planner: задержка подбора второго бревна привела к корректному перепланированию. После прогона добавлено ожидание обновления инвентаря; оно проверено тестом с задержанным подбором, но отдельный живой повтор после этого исправления не выполнялся. Это один успешный сценарий, а не полная проверка выживания или всех рецептов.

## Подготовка мира

1. Запусти vanilla Minecraft Java 1.21.1. Подойдёт отдельный сервер или мир, открытый по LAN. Для LAN используй порт, который показывает игра, а не автоматически 25565.
2. У точки появления агента должны быть доступные дубовые брёвна в радиусе 24 блоков. Для первого теста выбери ровную площадку с доступом к стволам, дневное время и без мобов рядом.
3. У агента должны быть права ломать блоки. Защищённая точка появления или плагины защиты могут запретить добычу.
4. Подключение Microsoft использует игровой аккаунт; если играешь сам одновременно, агенту нужен отдельный аккаунт. `offline` подходит только миру/серверу, который действительно принимает такой вход; это не обход проверки аккаунта.

## Запуск из исходников

В корне `mckudo_core` установи игровые зависимости только локально, не добавляя их в зависимости ядра:

```powershell
npm.cmd install --no-save --package-lock=false mineflayer mineflayer-pathfinder
```

Настрой подключение и запусти пример:

```powershell
$env:MC_HOST = "127.0.0.1"
$env:MC_PORT = "25565"
$env:MC_VERSION = "1.21.1"
$env:MC_AUTH = "offline"
$env:MC_USERNAME = "MCKudoAgent"
npm.cmd run demo:brain:mineflayer
```

Замени порт и идентификатор аккаунта. Вход Microsoft выполняется по инструкции Mineflayer в терминале; пароль не вставляется в код. Для своего offline-сервера укажи `MC_AUTH = "offline"` и ник `MCKudoAgent`.

Можно также использовать отдельное приложение первого теста, подготовленное рядом с библиотекой, если оно присутствует в рабочей папке. Оно не входит в npm-пакет ядра.

## Что наблюдать

В терминале печатаются `decision:trace` и результаты действий. Обычно цепочка состоит из двух операций добычи, двух операций крафта досок, изготовления верстака и палок; порядок может меняться из-за исходного инвентаря и реакций.

Результат засчитывается только если снимок настоящего инвентаря подтверждает верстак и палки. Проверь их наличие в игре. Одной строки «план построен» недостаточно. При достижении цели пример останавливает ядро и оставляет клиента подключённым для осмотра. Выход — Ctrl+C.

Если дуб не найден, цель блокируется с причиной. Если блок нельзя сломать, не хватает места или путь отсутствует, появляется `failure`. Неподтверждённый эффект отбрасывает план. Смерть ставит ядро на паузу; переподключение и возрождение этот короткий пример не автоматизирует.

## Ограничения крафта

`times` — число применений рецепта, не число выходных предметов. Верстак и палки можно изготовить в инвентаре. Для рецепта 3×3 адаптер ищет уже установленный верстак, подходит к нему и проверяет ингредиенты заново. Установка верстака в мир пока не реализована.

Отмена проверяется между отдельными операциями крафта. В Mineflayer нет `AbortSignal` для текущей транзакции `craft`, поэтому ядро ждёт её завершения перед следующей операцией. Сетевой сбой требует проверки фактического инвентаря.

Использованные API: [Mineflayer recipesFor / craft](https://github.com/PrismarineJS/mineflayer/blob/master/docs/api.md), [реализация craft](https://github.com/PrismarineJS/mineflayer/blob/master/lib/plugins/craft.js), [навигация mineflayer-pathfinder](https://github.com/PrismarineJS/mineflayer-pathfinder).
