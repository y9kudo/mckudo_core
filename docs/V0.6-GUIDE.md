# MCKudo Core 0.6.0: обучение, задачи и механика мира

MCKudo — библиотека принятия решений. KudoConnect подключается к серверу, получает мир и выполняет действия. Приложение создаёт клиента, подключает мозг и задаёт задачи. Автор обеих библиотек — **y9kudo**, лицензия MIT.

## Быстрый запуск панели

Из папки `mckudo_core`, в терминале VS Code:

```powershell
npm.cmd install
npm.cmd run dashboard
```

Открой `http://127.0.0.1:4180`. По умолчанию доступны Owen, Liam и Noah; сервер — Java 1.21.1, offline, `127.0.0.1:25565`.

1. Выбери агента в левой колонке и нажми **Подключить**.
2. Во вкладке **Задачи** выбери шаблон и нажми **+ Задача**.
3. Измени название, параметры, порядок кнопками ↑/↓. Удали ненужные блоки.
4. Нажми **Применить очередь**. Агент остановит прежнюю работу.
5. Нажми **Начать**. Статус каждой задачи отображается над редактором.

Вкладка **Код JSON** редактирует ту же очередь. Это декларативный JSON, который проверяется сервером панели. Для собственной JavaScript-логики используй библиотеку в приложении и подключаемые Reactor/навыки. Панель не исполняет произвольный JavaScript из текстового поля.

Пример очереди:

```json
[
  {
    "id": "wood",
    "title": "Собрать четыре любых бревна",
    "type": "scenario",
    "scenario": {
      "schemaVersion": 1,
      "name": "Древесина",
      "steps": [{ "id": "logs", "type": "resources", "targets": { "#logs": 4 } }]
    }
  },
  {
    "id": "table",
    "title": "Подготовить верстак",
    "type": "action",
    "action": { "skill": "ensureStation", "args": { "station": "crafting_table" } }
  }
]
```

`id` уникален внутри очереди. `title` — подпись в панели. `action` выполняет один навык, `scenario` проверяет условия этапов и выбирает последовательность действий. До 32 задач в очереди, до 64 этапов в сценарии. Формат этапов описан в [руководстве сценариев](SCENARIOS.md).

Успешный план ещё не завершает задачу: требуется результат исполнителя или наблюдение условий сценария. Одиночное действие с ошибкой останавливает очередь. Сценарий даёт своему планировщику выбрать альтернативу; после шести последовательных ошибок он также останавливается. Исправь её и примени очередь заново либо нажми **Повторить**, затем **Начать**. Повторное применение заменяет очередь и сбрасывает её отметки выполнения. Защита, питание и другие включённые политики мозга продолжают иметь собственные приоритеты.

**Инвентарь** показывает предметы и надетую броню. **Управление** позволяет назначить профиль выживания, передать предмет, выполнить ручное действие. **Обучение** показывает переходы, число обновлений весов и память неудач.

## Что именно обучается

`createMinecraftBrain()` по умолчанию подключает `createNeuralNavigator()`: небольшую локальную нейросеть **12 → 16 tanh → 1 sigmoid**. Она обучается обратным распространением ошибки и повторением сохранённых примеров. Платный API, GPU и языковая модель не нужны.

Входы: направление и длина перехода, изменение высоты, здоровье, сытость, количество близких игроков, измерение и вид движения. Выход — оценка риска неудачи. После восьми подтверждённых примеров оценка участвует в стоимости рёбер A*. Отдельная память временно повышает стоимость конкретной неудачной клетки. Поиск заново выбирает доступный маршрут.

Успех берётся из завершённого движения; урон учитывается как отрицательный исход. Отмена пользователем/другим действием не учит модель считать местность опасной. Длинный прямой пробег записывается как отдельные переходы между клетками, чтобы обучение соответствовало шагам планировщика.

Это обучение **навигационной оценки**, а не обучение всех игровых навыков с нуля. Крафт, бой и правила безопасности остаются отдельными алгоритмами. Нейросеть не разрешает ходить по неизвестным чанкам, игнорировать опору или превышать допустимый урон падения. `loss` — ошибка обучения, а не процент интеллекта или вероятность победы над драконом.

```js
import { createKudoConnect } from './kudoconnect/index.js';
import { createMinecraftBrain } from './mckudo_core.js';

const client = createKudoConnect({ username: 'Atlas', version: '1.21.1' });
await client.connect();
const brain = createMinecraftBrain({
  client,
  worldId: 'my-world',
  survival: { target: 'stone_tools' }
});
brain.start();
// brain.neural.snapshot() — статистика; brain.neural.export() — веса и опыт.
// await brain.stop(); await client.close(); — завершение приложения.
```

Для отключения обучения: `neural: false`. Для восстановления: `neural: { memory: savedMemory }`. Память ограничена 512 примерами, 256 неудачными клетками и 32 записями текущего журнала. Веса, опыт и ещё действующие неудачи экспортируются; текущий журнал и скользящая ошибка обучения начинают новую сессию.

Панель сохраняет веса, задачи и завершённые задачи каждые 15 секунд и при штатном завершении в `data/agents/<hash мира>/<имя>.json`. `createAgentManager({ memoryDirectory: 'data/agents', worldId: 'my-world' })` включает это в собственном приложении. Каталог `data/` исключён из Git. При новом мире поменяй `MC_WORLD`: опыт разных миров не следует смешивать. Библиотечный мозг вне менеджера сам файлы не записывает.

## Передвижение и игроки

Маршруты сочетают A*, обучаемую стоимость и локальное управление. Восемь направлений, плавный взгляд, разгон и торможение сохраняются. Обход игроков учитывает их наблюдаемую скорость на четыре физических тика вперёд и выбирает только проверенные проходы; spectator не считается физическим препятствием. Прыжок и спуск возле игрока сохраняют проверенное направление вместо блокировки из-за требования плоской поверхности.

В Overworld поиск рассматривает падения до 16 блоков, но допускает только те, которые проходят оценку урона и запаса здоровья. В Nether и End базовый предел — 3 блока. Это верхняя граница поиска, а не обещание пережить падение. Неизвестные блоки, опасные жидкости и пустота остаются препятствиями.

`dimensionTravelPolicy(dimension)` предоставляет приложению правила воды, кроватей, масштаба координат и рисков. `coordinateScale: 8` у Nether описывает соответствие координат Overworld; переход выполняет навык `enterPortal`, а не перенос координат вручную.

## Рецепты после подключения

Неиспользованный клиент не создаёт игровые реестры при конструировании. Подключение (либо явное обращение к `client.registry/world/inventory`) загружает данные выбранного профиля. Сам пакет `minecraft-data` остаётся зависимостью транспорта.

После входа Java 1.21.1 присылает целую книгу рецептов. Протокол не позволяет запросить у сервера только один рецепт, поэтому пакет сохраняется, а нормализованные рецепты индексируются **по требованию результата**:

```js
client.recipeBook.snapshot(); // source, announced, indexedOutputs, revision
client.recipeBook.recipesFor('crafting_table');
```

Повторная декларация рецептов очищает индекс. Планировщик и нативный крафт используют эту книгу; до её получения нативный крафт не подменяет её статическим списком. Специальные рецепты и рецепты с возвратом ёмкостей требуют исполнителя соответствующей механики. Наличие записи само по себе не означает поддержку её исполнения.

Для автономного анализа каталога без клиента остаётся `catalogFromMinecraftData(data)`. Для текущего мира: `catalogFromMinecraftData(client.registry, { recipeBook: client.recipeBook })`, затем `recipesFor(item)`. У такого каталога массовый `recipes()` запрещён, чтобы не разворачивать весь индекс неявно.

## Зелья и незерит

```js
import { planBrewing, planNetheriteUpgrade } from './mckudo_core.js';

const potion = planBrewing({
  registry: client.registry,
  potion: 'long_fire_resistance',
  bottles: 3,
  form: 'splash_potion'
});
// Вода → неловкое → огнестойкость → продление → взрывное.
console.log(potion);

const upgrade = planNetheriteUpgrade({
  registry: client.registry,
  item: 'diamond_chestplate',
  inventory: client.inventory.snapshot()
});
console.log(upgrade);
await client.execute({ skill: 'smith', args: { item: 'diamond_chestplate' } });
```

`planBrewing` возвращает цепочку ингредиентов, форму, до трёх бутылок и топливо. Есть базовые, продлённые, усиленные и испорченные зелья, а также эффекты 1.21. Это планировщик: **нативный исполнитель варки `brew` ещё не подключён**. Не передавай план напрямую в `execute()` как готовую варку.

`smith` — исполнитель улучшения для нативного профиля 1.21/1.21.1: алмазный предмет + незеритовый слиток + шаблон. Надетая броня сначала переносится в инвентарь. Нужен доступный кузнечный стол или материалы для его создания. Окно, результат, расход ингредиентов и компоненты проверяются по ответам сервера. Планировщик учитывает, что в обычной игре до 1.20 шаблон не требовался; наличие экспериментального предмета в реестре 1.19.4 не меняет это правило. Сам исполнитель старого протокола от этого не появляется.

`ensureStation` поддерживает `crafting_table`, `furnace`, `smithing_table`, `brewing_stand`. Последние две станции создаются из имеющихся материалов; автоматическая цепочка добычи всех их ингредиентов не встроена в этот низкоуровневый навык. Плавка `ancient_debris` в `netherite_scrap` добавлена в `smelt`.

## Порталы и End

```js
import { createNetherPortalBlueprint, billOfMaterials } from './mckudo_core.js';
const frame = createNetherPortalBlueprint({ origin: { x: 20, y: 64, z: 20 }, axis: 'x' });
console.log(billOfMaterials(frame)); // Рама 4×5: 14 обсидиана, включая углы.
```

Этап `netherPortal` выбирает наблюдаемую площадку или использует заданный `origin`, добывает материалы через мозг, размещает раму и поджигает. Нужна реальная безопасная площадка; неизведанная область не считается пустой.

`pillar` строит под ногами с обычным прыжком и серверным подтверждением, `descendPillar` разбирает собственный учтённый столб. Контроллер дракона планирует подъём к решётке, спуск и выстрел с дистанции. [Описание экспедиции и критерии победы](DRAGON-EXPEDITION.md). Полное прохождение с нуля до убийства дракона пока не подтверждено.

## Проверка

```powershell
npm.cmd run check
npm.cmd run test:live:learning
npm.cmd run test:live:recipes
```

Второй запуск требует работающего сервера. AtlasLearning проверяет получение книги мира, короткую очередь движения и восстановление нейросети из сохранённого файла. Он не получает предметы командами администратора. Отчёт — `data/learning-live-report.json`; при недоступном сервере, отсутствии пути или ошибке возвращается ненулевой код, а не фиктивный успех.

2 октября проверены три маршрута на Java 1.21.1, получение 1 290 серверных рецептов и восстановление модели: 15 переходов, 135 обновлений весов. 8 октября агент с пустым инвентарём добыл древесину, создал и установил верстак, сделал деревянную кирку; планировщик накопил 30 эпизодов и 324 обновления весов. [Полный отчёт и ограничения](TESTING-06.md). [Матрица совместимости версий](VERSIONS.md) отделяет данные от возможности полноценной игры.

Отдельная нейросеть планирования, PvP и запуск команды до 20 агентов описаны в [руководстве по обучению и команде](LEARNING-AND-TEAM.md).
