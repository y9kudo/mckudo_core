# MCKudo Core 0.7 · разработка

Автор **y9kudo**, MIT. Текущая версия исходников — `0.7.0`. [Описание релиза](releases/0.7.0.md) перечисляет вошедшие изменения и результаты проверок. Эта страница отделяет работающий код от этапов, которым ещё нужны исполнители или игровые испытания.

## Системы

| Система | Ответственность | Новый код |
|---|---|---|
| MCKudo Core | Цели, память, рецепты, сценарии, принятие решений | Машинный граф, водные миссии, журнал кампании |
| KudoConnect | Сессия Minecraft, пакеты, наблюдения и исполнение | Microsoft Auth, чтение GUI, посадка/выход из транспорта |
| KudoVectorize | Объём тела, пересечение препятствий, маршруты в 3D | Водный A*, контроль воздуха, предсказание шага элитр |

KudoVectorize не требует MCKudo или Mineflayer: `import {KudoVectorize} from 'kudoconnect/vectorize'`. При установке только ядра: `import {KudoVectorize} from 'mckudo/vectorize'`. Он получает функцию `getBlock`, поэтому применим и к другому адаптеру мира.

## Простой сценарий

В существующий сценарий добавляется обычный блок JSON:

```json
[
  {"get":"#logs","count":3},
  {"craft":"crafting_table"},
  {"swim":{"x":12,"y":62,"z":9}}
]
```

`swim` задаёт **клетку ног** в текущем измерении. Маршрут должен начинаться у доступной воды и проходить по загруженным клеткам. Это не команда автоматической поездки к удалённому океану через сушу. Приложение может предварительно вызвать `goTo` до берега.

```js
import {createMinecraftAgent} from '../mckudo_core.js';

const agent=createMinecraftAgent({name:'Atlas',worldId:'my-world'});
try {
  await agent.connect();
  await agent.swimTo({x:12,y:62,z:9});
} finally {
  await agent.close();
}
```

Координаты нужно заменить на существующий водный проход своего мира. Для установленного пакета импортируйте из `mckudo`. Подробности: [KudoVectorize](../packages/kudoconnect/docs/VECTORIZE.md), [Microsoft Auth](../packages/kudoconnect/docs/AUTHENTICATION.md), [серверные меню](../packages/kudoconnect/docs/MENUS-AND-TRANSPORT.md), [машинные рецепты](MACHINE-RECIPES.md).

## Экспедиция до дракона

Игровая проверка выявила и помогла исправить потерю деревьев в общей выборке окружения: сотни близких блоков камня занимали все места наблюдений. Теперь основные классы получают отдельные квоты. Для базового камня ядро предпочитает короткую безопасную лестницу, если рядом нет видимого блока в досягаемости. При полной сытости запас мяса готовится после первого инструмента (`hunting.reserveRequiresTools`, по умолчанию `true`); голодный агент может охотиться и без инструмента. Защита с `pathRetreat` выбирает геометрический отход при критическом здоровье; KudoConnect включает его, если объявлен навык `evade`.

Существующий профиль включает добычу инструментов, снаряжения и портальных материалов, Nether, стержни ифритов, жемчуг, глаза, поиск крепости, активацию существующего портала End и бой. End-портальные рамки в Survival не крафтятся: профиль ищет крепость.

```powershell
# Только проверка структуры профиля, без входа в игру:
node examples/dragon-expedition.js --check

# Полный игровой запуск; нужен сервер Java 1.21.1:
$env:MC_HOST="127.0.0.1"
$env:MC_PORT="25565"
$env:MC_NAME="RowanCampaign07"
$env:MC_WORLD_ID="my-world"
$env:MC_TEST_MINUTES="120"
node examples/dragon-expedition.js
```

Запуск требует нового живого игрока в Survival с пустым инвентарём. `MC_RESUME=1` разрешает продолжение с имеющимися предметами, но такое продолжение не подтверждает прохождение с нуля. Не выдавайте ресурсы тестовому игроку, если измеряется самостоятельная добыча.

Новый `expedition.snapshot().progress` содержит текущий этап, время без изменения ресурсов/этапов, статус `stalled` и ограниченный журнал. Перемещение по кругу не сбрасывает это время. Журнал помогает найти блокирующую механику, но сам не заменяет планировщик и не гарантирует восстановление. Завершение драконьей кампании требует серверного свидетельства смерти дракона и подтверждённого урона агента. Титры отдельно пока не проверяются.

**Полное автономное прохождение с нуля до дракона ещё не подтверждено.** Планирование элитр, полноценное управление лодкой, совместимость модовых сетевых профилей и реальные машинные исполнители остаются следующими этапами 0.7. Проверки Microsoft выполнялись с моделируемым провайдером; для настоящего входа нужен лицензированный аккаунт и интерактивный вход владельца.

Для длительного испытания с тем же игроком установи `MC_TEST_MINUTES=0`: срок не ограничивается таймером приложения. `MC_REPORT` задаёт JSON-снимок; рядом сохраняются полный журнал `.events.ndjson` и память `.memory.json`. После остановки тот же `MC_NAME`, `MC_WORLD_ID` и `MC_REPORT` вместе с `MC_RESUME=1` продолжают игру с серверным инвентарём и сохранёнными моделями. `MC_AUTO_RESPAWN=1` разрешает обычное возрождение после смерти, а `MC_MAX_DEATHS` ограничивает число возрождений за один запуск (по умолчанию 3); смерть и новый старт записываются в журнал. Отметка `originFromZero` сохраняет факт первоначального пустого инвентаря, а `resumed` явно помечает новый сегмент. [Текущий журнал полного испытания](results/full-survival-2026-10-13.md) отдельно отмечает проверенные этапы и оставшиеся пробелы.

## Проверки

```powershell
npm.cmd run check
npm.cmd run release:check
npm.cmd run test:package
npm.cmd run demo:machines
npm.cmd run test:live:07
```

`test:live:07` проверяет подключение, серверные рецепты, короткий маршрут без добычи/строительства и расчёт водного пути на реальных чанках. Отчёт находится в `data/v07-live.json`; данные мира не публикуются. Этот тест не выдаётся за испытание полёта или убийство дракона. Версии с суффиксом `-dev` проходят CI, но не создают стабильный GitHub Release автоматически.
