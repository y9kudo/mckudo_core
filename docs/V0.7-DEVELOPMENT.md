## Simple script

A conventional block is added to the current scenario JSON:

```json
[
  {"get":"#logs","count":3},
  {"craft":"crafting_table"},
  {"swim":{"x":12,"y":62,"z":9}}
]
```

`swim` it's a problem **leg cell** in the current measurement. The route should start at the available water and be run through the loaded cells. This isn't an automatic drive to the remote ocean through the land. The application may be previously called `goTo` to the shore.

```js
import {createMinecraftAgent} from '../overmindmc.js';

const agent=createMinecraftAgent({name:'Atlas',worldId:'my-world'});
try {
  await agent.connect();
  await agent.swimTo({x:12,y:62,z:9});
} finally {
  await agent.close();
}
```

Coordinates should be replaced by the existing water passage of their world. Import from `mckudo`. Details: [OMVectorize](../packages/omconnect/docs/VECTORIZE.md), [Microsoft Auth](../packages/omconnect/docs/AUTHENTICATION.md), [server menus](../packages/omconnect/docs/MENUS-AND-TRANSPORT.md), [Engine recipes](MACHINE-RECIPES.md).

## The Dragon Expedition

Game check revealed and helped correct the loss of trees in the total sample environment: Hundreds of nearby blocks of stone occupied all observation sites. The main classes now receive separate quotas. For base stone, the kernel prefers a short safe ladder, if there is no visible block in the vicinity. If complete, the meat reserve is prepared after the first instrument (`hunting.reserveRequiresTools`, default `true`); A hungry agent can hunt without a tool. Protection from `pathRetreat` Selects geometrically during critical health; OMConnect includes, if skills are declared `evade`.

Existing profile includes the extraction of tools, Equipment and port materials, Nether, Ifrates rods, Pearls, Eyes, Search for Fort, Activate existing portal End And fight. End-Portal framework in Survival No crafting: the profile is looking for a fortress.

```powershell
# Only profile structure check, Without entering the game:
node examples/dragon-expedition.js --check

# Full game launch; I need a server Java 1.21.1:
$env:MC_HOST="127.0.0.1"
$env:MC_PORT="25565"
$env:MC_NAME="RowanCampaign07"
$env:MC_WORLD_ID="my-world"
$env:MC_TEST_MINUTES="120"
node examples/dragon-expedition.js
```

Starting requires a new live player in Survival empty equipment. `MC_RESUME=1` Allows continuation with available items, But this extension doesn't confirm a passing from zero. Don't give resources to a test player, if the independent production is measured.

New `expedition.snapshot().progress` contains the current phase, time without change of resources/Phases, Status `stalled` and limited journal. Moving around doesn't take time away. A magazine helps find a blocking mechanic, But it doesn't replace the planner and it doesn't guarantee the recovery. The end of the dragon campaign requires a server-based proof of the death of the dragon and confirmed damage to the agent. The silences are not checked separately yet.

**Full autonomous passage from zero to dragon not yet confirmed.** Planning for the elite, Full-scale boat management, The compatibility of fashion network profiles and real machine performers remains the next steps 0.7. Checks Microsoft implemented with a simulated provider; For this entry, you need a licensed account and an interactive entry of the owner.

For a long test with the same player, set `MC_TEST_MINUTES=0`: The time limit is not limited to the timer of the annex. `MC_REPORT` it's a problem JSON-Photo; A full log is stored next to each other `.events.ndjson` and memory `.memory.json`. After stopping, same `MC_NAME`, `MC_WORLD_ID` and `MC_REPORT` with `MC_RESUME=1` Continue playing with server equipment and stored models. `MC_AUTO_RESPAWN=1` Allows normal recovery after death, a `MC_MAX_DEATHS` limits the number of rebirths per launch (default 3); Death and a new start are recorded in the magazine. Mark `originFromZero` Saves the original empty inventory, a `resumed` clearly marks a new segment.
