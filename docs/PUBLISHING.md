# GitHub и распространение

Исходники подготовлены как отдельный репозиторий **mckudo_core**. Удалённый репозиторий ещё не создан. Имя владельца GitHub нельзя достоверно определить по авторскому нику `y9kudo`; URL не выдумывается.

## Перед публикацией на GitHub

В корне проекта находятся MIT-лицензия, README, документы API, тесты и workflow CI. В `.gitignore` исключены токены, локальная память, зависимости и архивы npm.

```powershell
npm.cmd run check
npm.cmd run demo
npm.cmd pack --dry-run
git status
```

Создай пустой репозиторий `mckudo_core` в своём аккаунте GitHub. Из папки проекта выполни команды, подставив **настоящий URL своего репозитория**:

```powershell
git add .
git commit -m "Initial standalone MCKudo Core library"
git remote add origin URL_ТВОЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

В новой распакованной копии без `.git` сначала выполни `git init -b main`. Для коммита Git потребует уже настроенные имя и email автора; не используй вымышленный адрес. Войдите в GitHub штатным способом через VS Code или Git Credential Manager. Токен не вставляй в URL репозитория и не сохраняй в исходниках.

Публикация GitHub и публикация npm — разные действия. Даже до npm разработчик может установить библиотеку из локальной папки, `.tgz` или собственного опубликованного Git-репозитория.

## npm

1. Проверь доступность имени `mckudo` и право публиковать под этим именем. Если оно занято, выбери свободное scoped-имя под своим аккаунтом и обнови импорты документации.
2. Заполни `repository.url` и при необходимости `homepage`/`bugs` реальным адресом GitHub.
3. Запусти тесты и проверь содержимое `npm.cmd pack --dry-run`.
4. Войди в свой npm-аккаунт и публикуй только согласованную версию. `prepublishOnly` отклоняет публикацию, пока URL репозитория не заполнен.

CI выполняет тесты на Node 22 и 24 под Linux и Windows. Он не публикует пакеты, не использует игровые аккаунты и не выполняет вход в Minecraft. Обновления требуют повторных тестов; релизный тег должен соответствовать версии `package.json`.
