# Подключение MCKudo к KudoConnect

**Две самостоятельные библиотеки · автор y9kudo · MIT**

KudoConnect v0.5.0 находится в [packages/kudoconnect](../packages/kudoconnect/README.md). Он подключается к серверу, хранит наблюдаемое состояние и выполняет действия. MCKudo Core v0.5.0 хранит знания об игре, классы ресурсов, планы и опыт. Приложение соединяет библиотеки через адаптер.

## Простое приложение

После локальной установки обеих библиотек:

```js
import { createKudoConnect } from 'kudoconnect';
import { createCore } from 'mckudo';
import { createKudoAdapter } from 'mckudo/adapters/kudoconnect';

const client = createKudoConnect({ username: 'Alice', auth: 'offline', version: '1.21.1' });
let core, adapter;
try {
  await client.connect();
  adapter = createKudoAdapter(client, { trackedBlocks: ['#logs'], searchRadius: 64 });
  core = createCore({
    config: {
      schemaVersion: 4, name: 'Alice', worldId: 'my-server',
      actionTimeoutMs: 60000,
      rules: [{ id: 'wood', action: { skill: 'gather', args: { block: '#logs', count: 1 } } }]
    },
    adapter
  });
  console.log(await core.tick()); // один шаг
} finally {
  await core?.stop();
  adapter?.dispose();
  await client.close();
}
```

`core.start()` запускает постоянный цикл. В таком приложении обработайте остановку процесса и вызывайте `core.stop()`/`client.close()` при завершении. Для группы создайте `createFleet({ count: 2 })` и по одному адаптеру/Core на клиента.

Импорт `mckudo/connect` оставлен для совместимости: он экспортирует тот же выделенный клиент. Сам пакет `kudoconnect` не импортирует MCKudo. Он устанавливается отдельно из своего архива; публикации в npm пока не было.

## Где находятся знания

| MCKudo Core | KudoConnect |
| --- | --- |
| Цели, планировщик, правила и адаптивные сценарии | Сессия, пакеты, действия и отмена |
| Полный каталог конкретной версии и классы материалов | Полученные чанки, блоки, сущности и инвентарь |
| Ресурсные цепочки, инструменты, станции и топливо | Реальное исполнение только объявленных навыков |
| Тактические реакции и опыт | Физика, траектории и подтверждения сервера |
| Решение о совместной работе | Обмен сообщениями и намерениями вне чата |

Мозг не предполагает, что любой клиент умеет всё: `adapter.describe().skills` показывает доступные исполнители. Каталог может знать рецепт печи, даже если конкретный адаптер пока не реализовал работу с её окном. Сценарии крафта/зельеварения/полного прохождения требуют соответствующих исполнителей; независимый KudoConnect ещё расширяется.

## Наблюдение и классы

KudoConnect публикует собственный контракт `kudoconnect.agent` v1. Адаптер преобразует его в наблюдение MCKudo, дополняет нулевые количества известного инвентаря и сохраняет неизвестные блоки как неизвестные. Дальность поиска по умолчанию 128, настраивается до 512 блоков; результат ограничен чанками, которые отправил сервер.

Классы MCKudo передаются в клиентский реестр для выбранных `trackedBlocks`. Для самостоятельного KudoConnect доступны базовые `#logs`, `#leaves`, `#tree`, `#ores`, `#deepslate_ores`, `#crops`, `#workstations`; дополнительные классы регистрирует приложение.

## Проверки и дальнейшее развитие

В корне репозитория: `npm.cmd run check`. Отдельные тесты клиента: перейдите в `packages/kudoconnect` и выполните `npm.cmd test`. Игровая группа: `node packages/kudoconnect/examples/team.js`; переменная `MC_AGENTS` задаёт 1–10 клиентов. Этот пример только наблюдает и обменивается данными.

В Java 1.21.1 подтверждены вход, движение, добыча/подбор и одновременная работа семи новых клиентов. Полное прохождение, расширенная физика и стрельба в настоящем мире ещё не подтверждены. Чтение сетевых рецептов исправлено; актуальные результаты — в [отчёте 0.5.0](TESTING-05.md).
