# Экспедиция от пустого инвентаря до дракона

MCKudo принимает решения о ресурсах, пути и бое. KudoConnect выполняет действия на сервере и подтверждает их пакетами мира и инвентаря. Пример запуска соединяет эти библиотеки и сохраняет отчёт; алгоритмы подъёма и боя находятся в ядре.

## Запуск в PowerShell

Открой терминал в папке `mckudo_core`. Нужны Node.js 22+ и запущенный локальный сервер Java 1.21.1 с offline-входом.

```powershell
npm.cmd install
npm.cmd run test:dragon:check
$env:MC_HOST = '127.0.0.1'
$env:MC_PORT = '25565'
$env:MC_NAME = 'DragonRunner01'
$env:MC_TEST_MINUTES = '120'
npm.cmd run test:live:dragon
```

`--check` проверяет только конфигурацию. Для испытания с нуля используй новое английское имя: старт с предметами или надетой бронёй будет отклонён. Старое имя сохраняет данные игрока на сервере. Не выдавай агенту ресурсы командами и не бросай предметы: такой запуск уже не проверяет самостоятельное получение всего с нуля.

Отчёт сохраняется в `data/dragon-expedition.json`. Он содержит начальный и текущий инвентарь, действия с координатами, ошибки, этапы и события боя. `MC_REPORT` меняет путь; родительская папка должна существовать. `MC_TEST_MINUTES` задаёт бюджет 1–480 минут. Ctrl+C останавливает запуск. Возврат с кодом 1 и `incomplete` означает, что цель не достигнута, а не успешное прохождение.

## Что проверяет цель

Последовательность задаёт `dragonExpeditionScenario()`: каменные инструменты и печь → железо → алмазная кирка и материалы портала → броня, щит, лук, стрелы, блоки → Незер и стержни ифритов → жемчуг и глаза Эндера → поиск крепости по полётам глаз → активация существующих рамок → вход в End → бой.

Рамки портала в End не крафтятся: агент должен найти крепость и заполнить её рамки. Сценарий не использует `/give`, `/locate`, `/teleport`, seed или файлы мира.

`goalAchieved: true` требует завершения сценария, присутствия в End, серверного подтверждения смерти дракона и подтверждённого урона этого агента. Отправленная атака, найденный портал или исчезновение дракона недостаточны. Игроки, замеченные рядом, записываются в `playersObserved`; отсутствие там имён также не является доказательством полной изоляции мира.

## Подъём и спуск

```js
await client.execute({ skill: 'pillar', args: { count: 3, block: 'dirt' } });
await client.execute({ skill: 'descendPillar', args: { count: 3 } });
```

`pillar` выравнивает агента в центре опоры, прыгает обычной физикой и ставит блок только после подъёма ног выше его верхней грани. Каждый шаг ждёт блока в мире, расхода предмета и посадки. `count` — от 1 до 8; без `block` выбираются недорогие обычные полные блоки. Песок, гравий, станции и ценные блоки не расходуются. Нужны здоровье больше 8 и свободное пространство над головой. Смена измерения, коррекция позиции или отмена прекращают действие.

`descendPillar` разбирает только блоки, установленные этим экземпляром клиента и подтверждённые сервером. Каждый спуск ограничен одним блоком с известной опорой снизу. После переподключения память собственных столбов не сохраняется. Обычный `dig` по-прежнему не разрушает опору под агентом.

Отдельная проверка сама добывает три блока земли, поднимается и спускается:

```powershell
$env:MC_NAME = 'PillarRunner01'
npm.cmd run test:live:pillar
```

## Решения в End

`createDragonPolicy({ client })` проверяет баллистическую траекторию, приоритет кристаллов, облака дыхания и фазы дракона. Для решётки ищется доступная площадка с запасом блоков и свободной вертикальной колонной. Агент поднимается по одному блоку, открывает ближние прутья и разбирает свой столб перед выстрелом. `maxTowerHeight` ограничивает план подъёма: по умолчанию 48, допустимо 1–64.

Выстрел по кристаллу запрещён ближе 12 блоков; это минимальная дистанция политики, а не гарантия безопасности любого взрыва. Поворот к баллистическому направлению плавный. Во время сидящих фаз дракона стрелы сохраняются до взлёта. Удар по отдельной голове сидящего дракона пока не реализован.

`client.endgame` содержит подтверждения кристаллов — совпавшие по месту и времени взрыв и удаление сущности — и смерти дракона. Различаются общий факт смерти и участие агента. При ошибке декодирования пакета исполнение останавливается.

## Подключение из своего приложения

```js
import { createKudoConnect } from 'mckudo/connect';
import { createEndExpedition, dragonExpeditionScenario } from 'mckudo';

const client = createKudoConnect({ username: 'DragonRunner02', auth: 'offline' });
await client.connect();
const expedition = createEndExpedition({
  client,
  worldId: 'my-test-world',
  scenario: dragonExpeditionScenario()
});
await expedition.brain.start();
// При завершении приложения: await expedition.brain.stop(); await client.close();
```

Профиль добывает брёвна по доступным вариантам дерева, учитывает неудачные подходы, собирает ингредиенты перед возвращением к станции и ищет ближайших наблюдаемых мобов для нитей и перьев. Всё проверяется по фактическому инвентарю; таблица источников не обещает гарантированный дроп с каждого моба.

## Результаты и границы проверки

На локальном сервере 1.21.1 подтверждён самостоятельный сбор земли, подъём на три блока и разбор столба: здоровье 20/20, без коррекций позиции. Автоматические проверки отдельно покрывают решётку, план столба, препятствия, отмену и подтверждение победы.

Для отдельного повторного подключения к уже игравшему персонажу можно задать `$env:MC_RESUME='1'` и прежний `MC_NAME`. Отчёт отмечает `resumed:true` и сохраняет фактический начальный инвентарь; такое испытание само по себе не доказывает прохождение с нуля. Обычный запуск по-прежнему требует нового персонажа с пустым инвентарём и без брони. Используй новый `MC_REPORT`, чтобы сохранять отчёты предыдущих попыток.

В ресурсной части экспедиции работает общий CPU worker исследования. Контроллер запоминает наблюдаемые порталы по измерениям: при возвращении проверяет активный блок, а к выгруженной области идёт через подтверждённые пункты исследования. Старая координата сама по себе не разрешает вход в портал.

Полное прохождение с нуля и убийство дракона пока не подтверждены. Алгоритмы End необходимо отдельно проверить на настоящих башнях и драконе; успешная модель или готовый сценарий не заменяют такой прогон. Длительное прохождение зависит также от получения обсидиана возле жидкостей, поиска крепости Незера и безопасного перехода между областями мира.

Описание фаз для Java 1.21.1: [Yarn PhaseType](https://maven.fabricmc.net/docs/yarn-1.21.1+build.3/net/minecraft/entity/boss/dragon/phase/PhaseType.html). Форматы серверных сообщений: [minecraft-data protocol 1.21.1](https://github.com/PrismarineJS/minecraft-data/blob/master/data/pc/1.21.1/protocol.json).
