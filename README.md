# MCKudo Core

**Ядро автоматизации Minecraft · v0.2.0 · разработано y9kudo · MIT**

MCKudo — самостоятельная библиотека для создания систем автоматизации **Minecraft: Java Edition** на JavaScript. Она помогает описывать поведение агента: наблюдать за миром, выбирать приоритетную задачу, выполнять действия и проверять результат. Простые сценарии задаются в JSON, а новые игровые возможности добавляются через адаптеры и плагины.

Например, агент может сначала поесть, затем собрать нужное количество дерева и перейти к следующему этапу задачи. Ядро управляет порядком этих действий, повторными попытками и прогрессом. Подключение к Minecraft, перемещение и взаимодействие с блоками выполняет выбранный игровой адаптер.

**MCKudo не является готовым универсальным ботом или обученной нейросетью.** В текущей версии решения принимаются по заданным правилам и многошаговым сценариям. Понимание свободного чата, самостоятельное обучение, PvP и планирование произвольных рецептов не входят в готовые возможности.

## Как устроено ядро

```text
JSON: правила и задачи
        ↓
MCKudo Core: наблюдение → выбор действия → выполнение → проверка
        ↓
Адаптер: Mineflayer / симулятор / собственная интеграция
        ↓
Minecraft или тестовая модель мира
```

| Часть | Назначение |
|---|---|
| Конфигурация | Описывает условия, приоритеты, действия и зависимости шагов |
| Ядро | Выбирает доступное действие и контролирует его жизненный цикл |
| Адаптер | Читает состояние среды и выполняет реальные действия |
| Навык | Реализует конкретную операцию: например, `gather` или `goto` |
| Плагин | Объединяет дополнительные навыки с проверкой аргументов и зависимостей |
| Память | Сохраняет историю, счётчики и прогресс задач между запусками |
| Runtime | Координирует несколько агентов с ограничением параллельности |

Название репозитория — **mckudo_core**, имя пакета и импортов — **mckudo**, основной публичный файл — **mckudo_core.js**. Ядро не требует Mineflayer и не имеет внешних зависимостей времени выполнения. TypeScript-описания основного API входят в пакет.

## Возможности и интеграции

В версии 0.2.0 доступны:

- Реактивные правила с условиями и приоритетами.
- Многошаговые задачи с зависимостями и проверкой результата через `until`.
- Ограничение попыток, задержки повторов, пауза и отмена действий.
- Экспорт и восстановление прогресса задач.
- Пользовательские навыки и плагины.
- Работа нескольких агентов в одном процессе.
- Снимки состояния, история действий и события для собственного интерфейса.
- CLI для создания проекта, проверки JSON и запуска симуляции.

| Способ работы | Состояние | Доступные действия |
|---|---|---|
| Встроенный симулятор | Готов для локальных примеров и тестов | `eat`, `gather`, `craft`; небольшой фиксированный набор рецептов |
| Mineflayer | Адаптер реализован; нужен сервер и внешние пакеты | `eat`, `gather`, `goto` для vanilla-объектов |
| Собственный адаптер | Доступен публичный контракт | Определяются разработчиком |
| Forge / NeoForge | Подготовлен JS bridge-контракт | Нужны отдельный игровой мод и транспорт |
| Fabric | Предусмотрен тем же bridge-контрактом | Нужны отдельный игровой мод и транспорт |

**Готовых Forge/NeoForge/Fabric `.jar` в проекте пока нет.** Выбор имени загрузчика сам по себе не добавляет поддержку модов. Приоритет развития — Forge и NeoForge; подробности находятся в [матрице интеграций](docs/MODS.md).

Совместимость с версиями Minecraft определяется адаптером и его зависимостями. Ядро не обещает поддержку всех версий игры. Для Mineflayer проверь [список поддерживаемых версий](https://github.com/PrismarineJS/mineflayer#readme). Текущие автоматические проверки используют симулятор и тестовые адаптеры; они не заменяют проверку на настоящем сервере.

## Быстрый запуск без Minecraft

Требуется **Node.js 22 или новее**. Открой папку исходников `mckudo_core` в терминале VS Code:

```powershell
npm.cmd ci
npm.cmd run demo:workflow
```

Пример из [examples/workshop.json](examples/workshop.json) собирает два бревна, превращает их в доски и создаёт верстак и палки. Это **симуляция**, которая не подключается к серверу и не запускает игрового персонажа.

Другие команды из папки библиотеки:

```powershell
npm.cmd run demo
npm.cmd run demo:plugins
npm.cmd run demo:runtime
npm.cmd run cli -- validate examples/workshop.json
npm.cmd run cli -- simulate examples/workshop.json --steps 10
npm.cmd run check
```

`demo:runtime` запускает три независимых симулируемых агента. `check` проверяет конфигурации и выполняет тесты.

В примерах используется `npm.cmd`, чтобы команды работали в Windows PowerShell без изменения политики выполнения сценариев. В Linux и macOS используй `npm`.

## Установка в свой проект

Для воспроизводимого начала используй локальную копию библиотеки. Команды ниже выполняются **из папки `mckudo_core`**:

```powershell
npm.cmd run cli -- init ../my-automation
cd ../my-automation
npm.cmd install ../mckudo_core
npm.cmd start
```

CLI создаст соседнюю папку `my-automation` с файлами:

```text
my-automation/
  agent.json    — настройки и сценарий
  index.js      — запуск симулятора
  package.json  — настройки приложения
```

Существующая папка не перезаписывается. Полученный проект сразу работает без Minecraft. Для подключения к игре следуй следующему разделу.

В другом уже существующем приложении установи библиотеку по реальному пути:

```powershell
npm.cmd install "C:/path/to/mckudo_core"
```

Примеры ниже используют ES Modules. Укажи `"type": "module"` в `package.json` своего приложения или используй расширение `.mjs`. Созданный CLI проект уже настроен.

Публикация исходников на GitHub и публикация пакета в npm — разные действия. Эти инструкции не предполагают, что имя `mckudo` уже опубликовано в реестре npm. [Подробнее об установке и публикации](docs/PUBLISHING.md).

## Использование с Mineflayer

[Mineflayer](https://github.com/PrismarineJS/mineflayer) — библиотека подключения программного клиента к Minecraft Java. Она обеспечивает игровые действия, а MCKudo выбирает, когда их выполнять. Для поиска пути адаптер использует [mineflayer-pathfinder](https://github.com/PrismarineJS/mineflayer-pathfinder).

### 1. Установи зависимости приложения

В папке `my-automation`, созданной выше:

```powershell
npm.cmd install mineflayer mineflayer-pathfinder
```

### 2. Замени agent.json

Сценарий мастерской использует `craft`, которого пока нет в Mineflayer-адаптере. Для реального подключения используй этот полный пример: он ест хлеб при голоде и собирает до четырёх дубовых брёвен.

```json
{
  "schemaVersion": 2,
  "name": "ResourceAgent",
  "worldId": "my-minecraft-world",
  "tickIntervalMs": 1000,
  "rules": [
    {
      "id": "eat-first",
      "priority": 100,
      "when": {
        "all": [
          { "fact": "/self/food", "lt": 16 },
          { "fact": "/inventory/minecraft:bread", "gt": 0 }
        ]
      },
      "action": { "skill": "eat", "args": { "item": "minecraft:bread" } }
    },
    {
      "id": "collect-wood",
      "priority": 10,
      "when": { "fact": "/inventory/minecraft:oak_log", "lt": 4 },
      "action": { "skill": "gather", "args": { "block": "minecraft:oak_log", "count": 1 } }
    }
  ]
}
```

### 3. Создай minecraft.js

```js
import { readFile } from 'node:fs/promises';
import mineflayer from 'mineflayer';
import pathfinder from 'mineflayer-pathfinder';
import { createCore } from 'mckudo';
import { createMineflayerAdapter } from 'mckudo/adapters/mineflayer';

const config = JSON.parse(
  await readFile(new URL('./agent.json', import.meta.url), 'utf8')
);

const bot = mineflayer.createBot({
  host: process.env.MC_HOST || '127.0.0.1',
  port: Number(process.env.MC_PORT || 25565),
  username: process.env.MC_USERNAME || 'MCKudoAgent',
  auth: process.env.MC_AUTH || 'microsoft',
  version: process.env.MC_VERSION || false
});

bot.loadPlugin(pathfinder.pathfinder);
let core;

bot.once('spawn', () => {
  const movements = new pathfinder.Movements(bot);
  movements.canDig = false;
  movements.allow1by1towers = false;
  movements.maxDropDown = 2;
  bot.pathfinder.setMovements(movements);

  core = createCore({
    config,
    adapter: createMineflayerAdapter(bot, { goals: pathfinder.goals })
  });
  core.on('action:finish', result => console.log(result));
  core.start();
});

bot.on('death', () => { void core?.pause(); });
bot.on('end', () => { void core?.stop(); });
bot.on('kicked', reason => console.error('Отключён сервером:', reason));
bot.on('error', error => console.error(error.message));

process.once('SIGINT', async () => {
  await core?.stop();
  bot.quit();
});
```

### 4. Укажи сервер и запусти

В PowerShell:

```powershell
$env:MC_HOST = "127.0.0.1"
$env:MC_PORT = "25565"
$env:MC_AUTH = "microsoft"
$env:MC_USERNAME = "your-account-email@example.com"
node minecraft.js
```

Замени адрес, порт и идентификатор аккаунта своими значениями. Для Microsoft-авторизации следуй инструкциям входа в терминале; пароль не записывается в код. На сервере с проверкой аккаунтов нужен аккаунт, имеющий доступ к Minecraft Java. Подробнее — [авторизация Mineflayer](https://github.com/PrismarineJS/mineflayer#echo-example).

Для своего тестового сервера, который уже настроен на offline-авторизацию, можно установить `MC_AUTH` в `offline`, а `MC_USERNAME` — в `MCKudoAgent`. Это не способ войти на сервер с Microsoft-проверкой. Для мира, открытого по LAN, укажи порт, показанный игрой.

Без `MC_VERSION` Mineflayer определяет версию сервера автоматически. Это не расширяет список поддерживаемых версий. При необходимости задай `MC_VERSION` в соответствии с сервером и поддержкой установленного Mineflayer.

Для сценария нужен доступный дуб в радиусе поиска 24 блоков и место в инвентаре. Хлеб должен уже находиться у агента. Он не создаёт предметы из ничего. При отсутствии пути, нужного блока или инструмента действие завершается ошибкой с повтором после задержки. Пример приостанавливается при смерти; автоматическое восстановление и переподключение приложение должно организовать отдельно.

| Навык адаптера | Аргументы | Поведение |
|---|---|---|
| `eat` | `item`, по умолчанию `minecraft:bread` | Ест указанный предмет из инвентаря |
| `gather` | `block`, `count` от 1 до 16 | Ищет блок, подходит, добывает и приближается к выпавшим предметам |
| `goto` | Числа `x`, `y`, `z`; `range` от 0 до 16 | Идёт к заданным координатам |

Успешная добыча блока сама по себе не гарантирует нужного количества предметов в инвентаре: используй `until` в многошаговой задаче для проверки фактического результата. Модовые ID и `craft` этот адаптер пока не поддерживает.

## Использование без Mineflayer

### Вариант A: встроенный симулятор

В приложении с установленным `mckudo` создай `simulate.js`. Можно использовать `agent.json` из предыдущего раздела или сценарий, созданный CLI:

```js
import { readFile } from 'node:fs/promises';
import { createCore } from 'mckudo';
import { createSimulator } from 'mckudo/adapters/simulator';

const config = JSON.parse(
  await readFile(new URL('./agent.json', import.meta.url), 'utf8')
);
const core = createCore({ config, adapter: createSimulator() });

core.on('action:finish', result => console.log(result));
for (let step = 0; step < 10; step++) {
  await core.tick();
}
console.log(core.snapshot());
await core.stop();
```

```powershell
node simulate.js
```

Это способ изучить JSON, проверить порядок действий и разработать интерфейс без игрового аккаунта. Симулятор моделирует только небольшой набор состояний и рецептов, а не весь Minecraft.

### Вариант B: собственный игровой адаптер

Чтобы управлять настоящим Minecraft без Mineflayer, нужно самостоятельно связать ядро с игровым клиентом, модом или другим API. Адаптер предоставляет три метода:

| Метод | Что должен делать |
|---|---|
| `describe()` | Синхронно возвращать версию протокола и список реализованных навыков |
| `observe({ signal })` | Асинхронно возвращать состояние среды в виде обычного JSON |
| `execute(action, { signal })` | Выполнять действие и завершаться после его выполнения или остановки |

Каркас ниже показывает контракт. Он намеренно не выполняет игровых действий, пока разработчик не реализует оба метода:

```js
const adapter = {
  describe() {
    return {
      protocolVersion: 1,
      kind: 'custom',
      loader: 'vanilla',
      minecraftVersion: 'your-tested-version',
      skills: ['gather']
    };
  },
  async observe({ signal }) {
    signal.throwIfAborted();
    // Прочитай состояние через свой игровой API и верни JSON.
    throw new Error('Реализуй чтение игрового состояния');
  },
  async execute({ skill, args }, { signal }) {
    signal.throwIfAborted();
    // Выполни навык через свой API; обрабатывай signal до конца действия.
    throw new Error('Реализуй выполнение игрового действия');
  }
};
```

После реализации передай объект в `createCore({ config, adapter })`. Адаптер должен обрабатывать отмену и возвращать JSON без объектов сокетов или игровых классов. Если действие невозможно, выбрасывай исключение или возвращай `{ ok: false, message: 'Причина' }`.

### Вариант C: мост к Forge / NeoForge / Fabric

Экспорт `mckudo/adapters/bridge` содержит `createBridgeAdapter`. Для него разработчик передаёт собственный `transport` с методами `describe`, `observe`, `execute` и `cancel`, а также `expectedLoader`: `forge`, `neoforge` или `fabric`.

Мост проверяет совместимость протокола и подтверждение отмены. Однако сам сетевой транспорт и Java-мод ещё нужно реализовать. Сейчас это точка расширения, а не готовая инструкция установки мода. [Контракт и требования к модам](docs/MODS.md).

## Как читать конфигурацию JSON

| Поле | Значение |
|---|---|
| `schemaVersion` | Версия формата JSON, а не Minecraft. Для новых сценариев используй `2` |
| `name` | Имя агента внутри ядра; не меняет ник игрового аккаунта |
| `worldId` | Идентификатор мира для памяти; не адрес сервера |
| `tickIntervalMs` | Пауза между автоматическими циклами после завершения предыдущего |
| `rules` | Повторяемые реакции на состояние среды |
| `workflows` | Задачи из нескольких связанных шагов |
| `priority` | Чем больше число, тем выше приоритет доступного действия |
| `when` | Условие выбора правила или активации задачи |
| `action` | Имя навыка и его аргументы |
| `until` | Проверяемый результат шага многошаговой задачи |

`/inventory/minecraft:oak_log` — путь к количеству дубовых брёвен в наблюдении. Операторы `lt`, `gte` и `eq` означают «меньше», «больше или равно» и «равно». Условия объединяются через `all`, `any` и `not`; JavaScript в JSON не выполняется.

Правило может срабатывать снова, пока выполняется его условие. Многошаговая задача сохраняет завершённые этапы и заканчивается после выполнения всех шагов. По умолчанию шаг зависит от предыдущего; `dependsOn` позволяет задать другие зависимости. `until` проверяется по наблюдению, в том числе после действия. Число попыток ограничивается `maxAttempts`.

Готовый пример цепочки с крафтом — [examples/workshop.json](examples/workshop.json); он предназначен для симулятора. [Полный справочник JSON](docs/JSON.md) и [описание задач](docs/WORKFLOWS.md).

## Управление и сохранение прогресса

После создания `core` доступны:

| Вызов | Результат |
|---|---|
| `await core.tick()` | Выполнить один цикл |
| `core.start()` | Включить автоматический цикл |
| `await core.pause()` | Приостановить работу и запросить отмену текущего действия |
| `core.resume()` | Снять паузу; не создаёт таймер, если `start()` не вызывался |
| `await core.stop()` | Остановить автоматический цикл и запросить отмену |
| `core.snapshot()` | Получить копию состояния, истории и прогресса |
| `core.resetWorkflow(id)` | Сбросить задачу для повторного выполнения |
| `core.retryStep(workflowId, stepId)` | Разрешить повтор ошибочного или прерванного шага |

Операции изменения задач выполняются между действиями. Тайм-аут и остановка используют `AbortSignal`: если адаптер игнорирует отмену, ядро ждёт завершения, чтобы не запустить пересекающиеся действия.

Память сохраняется явно. Следующий фрагмент использует уже подготовленные `config` и `adapter`:

```js
import { FileMemory } from 'mckudo/memory';

const store = new FileMemory('./data/world-one.json');
const core = createCore({ config, adapter, memory: await store.load() });
await core.tick();
await store.save(core.exportMemory());
await core.stop();
```

Сохраняется прогресс ядра, а не мир Minecraft или инвентарь. Для одного файла нужен один писатель. Прерванный шаг с неизвестным результатом не повторяется автоматически после восстановления: разработчик должен проверить состояние игры. Изменение определения задачи может потребовать миграции памяти. [API и восстановление](docs/API.md).

## Расширение и документация

Навыки добавляются через `registerSkill`, а наборы навыков — через `definePlugin` и `core.use`. Плагины исполняют доверенный JavaScript в процессе приложения; это не изолированная среда.

`MckudoRuntime` управляет несколькими ядрами и ограничивает одновременную работу. Каждому игровому подключению назначается собственный `resourceKey`. Это координация внутри одного процесса, а не распределённый кластер или автоматическая командная стратегия.
