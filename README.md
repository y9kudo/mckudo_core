## Что такое MCKudo

MCKudo Core — импортируемая библиотека для разработчиков систем автоматизации Minecraft. Она связывает знания об игре, наблюдения, планирование, реакции и выполнение задач. Приложение на её основе может управлять одним игровым агентом, несколькими агентами или собственной средой моделирования.

**MCKudo является мозгом агентов.** Игрового клиента создаёт приложение. Самостоятельный **KudoConnect** подключается к серверу и выполняет действия; ядро выбирает задачи, хранит знания и опыт, строит планы, реагирует на изменения и проверяет результаты. KudoConnect можно использовать без MCKudo, а MCKudo — с другими адаптерами. Прежняя интеграция Mineflayer сохранена отдельно для совместимости и испытаний.

Простое поведение настраивается в JSON. Библиотека также предоставляет JavaScript API и типы TypeScript для собственных планировщиков, классов блоков, навыков и интеграций.

```text
Приложение разработчика
        ↓
MCKudo Core
  каталоги / классы / цели / Planner / Reactor / маршруты / память
        ↓
Адаптер и исполнители навыков
        ↓
Minecraft-клиент, игровой мод или тестовая среда
```

## Первый запуск KudoConnect

Для своего offline-сервера Java 1.21.1 на `127.0.0.1:25565`:

```powershell
git clone https://github.com/y9kudo/mckudo_core.git
cd mckudo_core
npm.cmd ci
npm.cmd run demo:kudoconnect -- observe
npm.cmd run demo:kudoconnect -- walk
npm.cmd run demo:kudoconnect -- gather
```

`observe` проверяет подключение, `walk` выполняет короткий безопасный маршрут, `gather` добывает и подбирает один ближайший достижимый ствол класса `#logs`. Отчёты находятся в `data/`. Это реальные игровые действия в survival. [Полная инструкция и API KudoConnect](docs/KUDOCONNECT.md).

Подключение в своём приложении:

```js
import { createKudoConnect } from 'mckudo/connect';
import { createKudoAdapter } from 'mckudo/adapters/kudoconnect';
```

Первый профиль клиента ограничен Java 1.21.1 и offline. Общие каталоги и планировщики ядра шире набора его текущих игровых исполнителей; проверяй возможности через `adapter.describe().skills`. Поддержка ИИ-агентов уровня v1.0.0 остаётся направлением развития ядра, а не заявлением о завершённой версии.

## Быстрый запуск проверок

Нужен Node.js 22 или новее. В терминале VS Code, открытом в папке проекта:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run demo:library
npm.cmd run demo:navigation
```

`demo:library` рассчитывает ресурсы и выполняет строительство укрытия в симуляторе. `demo:navigation` рассчитывает маршрут с мостом через двухблочный разрыв. Эти примеры работают локально, без сервера и платного API.

## Импорт библиотеки

Из соседней папки проекта приложения:

```powershell
npm.cmd install ../mckudo_core
```

В `package.json` приложения укажи `"type": "module"`, затем используй:

```js
import { createCore, createBlockTaxonomy, planResources } from 'mckudo';
```

Имя npm-пакета в проекте — `mckudo`, название ядра — **MCKudo Core**, репозиторий/папка — `mckudo_core`. Локальная установка доступна сразу. Публикация в реестре npm выполняется отдельно: [руководство](docs/PUBLISHING.md).

## Блоки, классы и рецепты

```js
import minecraftData from 'minecraft-data';
import {
  catalogFromMinecraftData, createBlockTaxonomy,
  resourceSources, planResourceClasses
} from 'mckudo';

const catalog = catalogFromMinecraftData(minecraftData('1.21.1'));
const classes = createBlockTaxonomy(catalog);

console.log(classes.classesOf('minecraft:acacia_leaves')); // tree, leaves, …
console.log(classes.members('deepslate_ores'));

const plan = planResourceClasses({
  catalog,
  targets: { '#planks': 8 },
  sources: resourceSources(catalog, {
    availableBlocks: ['minecraft:acacia_log']
  })
});
console.log(plan.resolvedTargets); // { 'minecraft:acacia_planks': 8 }
console.log(plan.actions);
```

`availableBlocks` заполняется наблюдениями адаптера. Ядро проверяет реальные рецепты: отнесение листвы к `tree` не делает её ингредиентом досок. Для железа `iron_ore` и `deepslate_iron_ore` становятся альтернативными источниками `raw_iron` с подходящим инструментом.

`minecraft-data` предоставляет реестры и варианты крафта. Для **всех файлов рецептов и тегов** конкретной Java-версии импортируй её локальный JAR или ZIP datapack:

```js
import { readJavaDataArchive, catalogFromMinecraftData } from 'mckudo';
const data = await readJavaDataArchive('C:/Minecraft/1.21.1.jar');
const catalog = catalogFromMinecraftData(minecraftData('1.21.1'), {
  vanillaRecipes: data.recipes,
  tags: data.tags
});
const classes = createBlockTaxonomy(catalog, { tags: data.blockTags });
```

Архив читается как источник JSON; игровой код не запускается. Для vanilla 1.21.1 проверены **1060 блоков, 1333 предмета, 1290 файлов рецептов, 184 тега блоков и 147 тегов предметов**. Все записи доступны разработчику; `recipe.executable` и `recipe.reason` показывают поддержку исполнения типа рецепта. Крафт, плавка, копчение и плавильная печь имеют исполнители; специальные рецепты сохраняют исходную запись для расширений. [Каталог и правила исполнения](docs/AUTOMATION.md#каталог-и-рецепты).

## Подключение Mineflayer

Готовый пример приложения: [examples/resources-mineflayer.js](examples/resources-mineflayer.js). Он создаёт клиента, подключает ядро, защиту и питание, выбирает доступную древесину и ставит цель получить деревянную кирку. Жизненный цикл соединения находится в примере приложения.

Для своего локального **offline**-сервера:

```powershell
$env:MC_HOST = '127.0.0.1'
$env:MC_PORT = '25565'
$env:MC_VERSION = '1.21.1'
$env:MC_AUTH = 'offline'
npm.cmd run demo:resources:mineflayer
```

Для сервера с проверкой аккаунта используй `MC_AUTH=microsoft` и вход через Mineflayer. Для полного каталога рецептов можно задать `MC_DATA_ARCHIVE` — путь к JAR той же версии. Настройки восприятия находятся в [examples/perception.json](examples/perception.json).

Состав ядра в приложении:

```js
const adapter = createMineflayerAdapter(bot, {
  goals: pathfinder.goals, catalog, taxonomy,
  searchRadius: 128,
  entityRadius: 128,
  requestedViewDistance: 16
});
const core = createCore({
  config: {
    schemaVersion: 4, name: 'MyAgent', worldId: 'my-world',
    actionTimeoutMs: 60000
  },
  adapter,
  preemptionMs: 100,
  reactors: [
    createDefenseReactor({ attackPlayers: false }),
    createFoodReactor({ catalog, allowHunting: true }),
    createResourceReactor({
      catalog, targets: { 'minecraft:wooden_pickaxe': 1 },
      stations: { 'minecraft:crafting_table': { x: 10, y: 64, z: 12 } }
    })
  ]
});
core.start();
```

Это фрагмент после подключения клиента и загрузки чанков; полные импорты и обработка отключения есть в файле примера. Координату станции выбирают по свободному месту в своём мире. Сервер определяет фактическую дальность загрузки чанков. Радиус поиска ограничивает работу с уже полученными блоками; неизвестные ячейки сохраняются неизвестными.

## Использование без Mineflayer

Все модели каталогов, классов, рецептов, маршрутов и строительства доступны независимо от клиента. `createCore` принимает адаптер с тремя методами:

```js
const adapter = {
  describe: () => ({
    protocolVersion: 1, perceptionVersion: 1,
    kind: 'my-client', loader: 'vanilla',
    minecraftVersion: '1.21.1', skills: ['gather']
  }),
  observe: async ({ signal }) => {
    signal.throwIfAborted();
    return myClient.readObservation();
  },
  execute: async (action, { signal }) => {
    return myClient.executeAndConfirm(action, signal);
  }
};
```

`myClient` — твоя реализация транспорта/исполнителя. Она должна подтвердить завершение действия или вернуть ошибку, а при отмене дождаться остановки работы. Поставляются симуляторы для тестов и контракт bridge для игровых адаптеров Forge, NeoForge и Fabric. Исполняемые Java-моды и матрица совместимости с модпаками развиваются отдельно от контракта: [MODS.md](docs/MODS.md).

## Основные модули

| Модуль | Назначение |
|---|---|
| Catalog | Реестры, поиск по ID, рецепты и альтернативные ингредиенты |
| BlockTaxonomy | Множественные классы, иерархии, теги и выборки блоков |
| Resource Planner / Reactor | Цепочки добычи и производства, выбор следующего действия по свежему наблюдению |
| Navigation / Exploration | A*, стоимость пути, мосты, контролируемая добыча и точки исследования |
| Food / Defense Reactor | Питание, производство еды, реакция на угрозы и прерывание работы |
| Construction | Чертежи, материалы, очередность установки и проверка результата |
| Survival Progression | Упорядоченные этапы и сохранение достигнутых вех |
| GoalBrain / Planner | Планирование по желаемому состоянию и каталогу операторов |
| Workflow | Зависимости шагов, постусловия, повторы и восстановление |
| Runtime / Plugins | Несколько агентов, дополнительные навыки и ограничения параллельности |
